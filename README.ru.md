# Bad CRM

**Self-hosted multi-tenant рабочее пространство для команд разработки.** Проекты, канбан-задачи,
блочные документы, markdown-база знаний, файлы, тайм-трекинг, дашборды, командный чат,
E2EE-хранилище паролей, защищённые ссылки, статусы GitHub Actions и AI-ассистент — в одной
инсталляции, с единой моделью данных, единой моделью прав и одной командой `docker compose up`.

Лицензия — **AGPL-3.0-or-later**. Интерфейс на **английском и русском**.

## Что это

Bad CRM — рабочее пространство для команд разработки примерно от 5 до 50 человек. Он существует
потому, что сегодня этот контекст размазан по шести-семи несвязанным SaaS-сервисам: задача живёт в
одном инструменте, её спецификация — в другом, обсуждение — в третьем, доступы к стенду — в
четвёртом, потраченные часы — в пятом.

Ключевая ставка — не «ещё один трекер задач», а **связность**: проект и сотрудник — две центральные
модели, к которым пристёгнуто всё остальное: задачи, документы, знания, файлы, секреты, время, чат,
пайплайны и деньги. Один граф, один поиск, одна модель прав, одна установка.

Слово «CRM» здесь означает управление отношениями с **заказчиком проекта разработки** (контракт,
сроки, приёмка, инвойсы), а не продажи.

## Для кого

| Роль | Что получает |
|---|---|
| **Разработчик** | Задачи, спецификации, чат и таймер в одном месте; полный контекст задачи без переключения инструментов |
| **Тимлид** | Планирование, ревью, загрузка и отчёты по времени в разрезе людей и проектов |
| **Проектный лидер / PM** | Клиенты, контракты, бюджет против burn, приёмка вех, звонки и принятые на них решения |
| **Администратор организации** | Одно место для онбординга и офбординга человека, одна модель прав для выдачи и отзыва доступа |
| **Владелец инсталляции** | Данные на своём железе, отсутствие поштучной оплаты, возможность форкнуть и проаудировать |

## Чем принципиально не является

Не sales-CRM (нет воронок и лидов), не helpdesk для внешних клиентов, не HR-система (нет
рекрутинга, ревью и компенсаций), не конструктор произвольных BI-отчётов, не маркетплейс плагинов.
И не хостится нами: SaaS-версии нет и не планируется.

(функции скрыты в UI и возвращают внятное «функция выключена»).

## Быстрый старт

> **Пока недоступно.** Self-hosted альфа выходит в **EPIC-017**, в конце майлстоуна M2. До этого
> нет образа, который можно вытянуть, и нет compose-файла, который можно запустить. Команды ниже —
> проектируемый интерфейс, записанный здесь, чтобы дизайн можно было отревьюить; сегодня они не
> работают.

### Требования (планируемые)

| | Минимум | Рекомендуется |
|---|---|---|
| CPU / RAM | 2 vCPU / 2 GB (профиль `minimal`) | 2 vCPU / 4 GB (профиль `default`) |
| Диск | 10 GB + ваши данные | SSD с запасом под файлы и бэкапы |
| Софт | Docker 24+ с Compose v2 | То же плюс reverse-proxy с TLS |
| ОС | Linux (x86-64 или arm64) | То же |

### Как это задумано

```bash
git clone https://github.com/<org>/bad-crm.git
cd bad-crm
cp .env.example .env
# сгенерировать обязательный ключ шифрования
openssl rand -base64 32          # → APP_ENCRYPTION_KEY
docker compose up -d
```

Дальше — открыть приложение, создать первую организацию и стать её владельцем. Полная процедура,
включая обязательный чек-лист безопасности после установки, — в
[`docs/runbooks/install.md`](docs/runbooks/install.md).

Профиль `minimal` не поднимает Meilisearch и запускает воркеры внутри процесса API — для небольших
инсталляций на скромном железе.

## Конфигурация

Конфигурация — только переменные окружения, разобранные схемой один раз при старте. Ошибка
конфигурации означает отказ старта, а не 500 через час работы.

**Обязательные:**

| Переменная | Что это |
|---|---|
| `APP_URL` | Публичный URL инсталляции; используется для CORS, cookie и ссылок в письмах |
| `DATABASE_URL` | Строка подключения к PostgreSQL под ролью приложения (она **не** должна иметь `BYPASSRLS`) |
| `REDIS_URL` | Строка подключения к Redis |
| `JWT_SECRET` | Секрет подписи короткоживущих access-токенов, минимум 32 символа |
| `APP_ENCRYPTION_KEY` | 32 байта в base64 — шифрует секреты интеграций at rest. **Потеря ключа делает сохранённые креды интеграций невосстановимыми** |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Объектное хранилище для файлов |

**Опциональные (отсутствие деградирует функцию, но не ломает старт):**

| Переменная | Что будет, если не задана |
|---|---|
| `SMTP_URL` | Письма пишутся в лог (dev) / почтовые операции падают с внятной ошибкой (prod) |
| `MEILI_HOST`, `MEILI_MASTER_KEY` | Поиск падает на полнотекст PostgreSQL; в UI баннер об ограниченных возможностях |
| `AI_ENABLED` | AI-функции скрыты в UI и возвращают `feature_disabled` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Трейсы не экспортируются; логи и метрики работают |
| `LOG_LEVEL` | По умолчанию `info` |

**API-ключи LLM-провайдеров никогда не живут в переменных окружения.** Их вводит администратор
организации в интерфейсе, и хранятся они зашифрованными в базе. `AI_ENABLED` — только
общеинсталляционный выключатель.

Полный список с комментариями и безопасными дефолтами будет в `.env.example` (создаётся в EPIC-001).

## Архитектура

```
                Браузер (React 19 + Vite)
                 ─ единственное место, где vault расшифрован
                          │ HTTPS / WebSocket
                          ▼
              Reverse-proxy (TLS, sticky /socket.io)
                          │
        ┌─────────────────┴──────────────────┐
        │   Образ приложения (один образ)    │
        │   ROLE=api          ROLE=worker    │
        │   Express 5, гексагональная арх.   │
        └─────────────────┬──────────────────┘
                          │
   ┌──────────┬───────────┼───────────┬─────────────┐
   ▼          ▼           ▼           ▼             ▼
PostgreSQL   Redis      MinIO    Meilisearch      SMTP
16+pgvector  7          (S3)     (опционально)
изоляция     очереди,   файлы    поиск
через RLS    pub/sub
```

Ключевые решения, у каждого свой ADR:

- **Мультиарендность через PostgreSQL Row Level Security**, а не через «мы не забыли добавить
  `WHERE`» — второй, независимый рубеж ниже приложения ([ADR-0004](docs/architecture/adr/0004-multi-tenancy-postgres-rls.md)).
- **Гексагональный backend**: доменные правила и политики доступа чистые и тестируются без БД,
  инфраструктура заменяема ([ADR-0002](docs/architecture/adr/0002-hexagonal-backend-express-prisma.md)).
- **Contract-first API**: OpenAPI 3.1 — источник истины, правится руками в ревью; типы клиента
  генерируются из спеки, двусторонний контрактный тест ломает сборку при расхождении ([ADR-0003](docs/architecture/adr/0003-openapi-as-source-of-truth.md)).
- **Транзакционный outbox**: доменные события пишутся в той же транзакции, что и данные, и уже потом
  разъезжаются по очередям — ничего внешнего внутри транзакции ([ADR-0021](docs/architecture/adr/0021-transactional-outbox.md)).
- **Zero-knowledge vault**: ключи выводятся и используются только в браузере; сервер держит
  шифротекст и метаданные и не может расшифровать ничего ([ADR-0009](docs/architecture/adr/0009-e2ee-vault-key-hierarchy.md)).

Вся документация: [`docs/README.md`](docs/README.md) — начинать оттуда.
Архитектурный обзор: [`docs/architecture/overview.md`](docs/architecture/overview.md).
Все 21 решение: [`docs/architecture/adr/`](docs/architecture/adr/).

## Участие в разработке

Вклад приветствуется — проект находится в той фазе, когда обратная связь по дизайну ценнее кода.
Перед пул-реквестом прочитайте [`CONTRIBUTING.md`](CONTRIBUTING.md). Коротко:

- Работа идёт в рамках эпика и истории; кода без них не бывает.
- **TDD обязателен** — сначала падающий тест.
- Каждый коммит проходит гейт из шести проверок и правила из [`rules/`](rules/).
- Коммиты — Conventional Commits, на английском.
- Используется **DCO** (`Signed-off-by`), а не CLA.

Также прочитайте [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md).

## Безопасность

**Не** сообщайте об уязвимостях через публичные issue. Канал приёма, сроки ответа, скоуп и политика
раскрытия — в [`SECURITY.md`](SECURITY.md).

[`docs/security/e2ee-design.md`](docs/security/e2ee-design.md) и

доверять свои секреты любому продукту, включая этот.
