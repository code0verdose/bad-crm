# ADR-0006 — UI на Mantine 7 со стилизацией через CSS Modules, без Tailwind

## Контекст

Интерфейс Bad CRM — это не набор лендингов, а плотное рабочее приложение. Инвентарь экранов из
[`../ux-architecture.md`](../ux-architecture.md) включает: канбан-доску с перетаскиванием, таблицы
таймшитов и аудита с виртуализацией, матрицу ролей и прав, дровер карточки задачи, календарь
звонков, редактор документов, граф базы знаний, чат с бесконечной лентой, модалки подтверждения
разрушающих действий, датапикеры с диапазонами, комбобоксы с асинхронным поиском, формы настроек.

Это означает, что **основная стоимость UI — не в стилях, а в поведении сложных компонентов**:
управление фокусом в оверлеях, доступность комбобокса с клавиатуры, портал и позиционирование
поповера, ловушка фокуса в модалке, корректный `aria-*` у таблицы с сортировкой. Каждый такой
компонент, написанный самостоятельно, — это недели работы и постоянный источник a11y-регрессий.

Второе обстоятельство: **тема и тёмный режим должны быть едиными по всему продукту**, включая
графики ([ADR-0017](0017-charts-mantine-charts.md)), редактор документов
([ADR-0012](0012-docs-editor-blocknote-json-content.md)) и календарь. Любой второй источник стилевой
правды означает два набора токенов, которые расходятся при первом же изменении палитры.

Третье: **проект интернационализирован EN/RU** ([ADR-0019](0019-i18n-en-ru-i18next.md)). Русский
текст в среднем на 15–30 % длиннее английского, отдельные термины — вдвое. Значит, вёрстка не может
опираться на фиксированные ширины, а компоненты обязаны корректно переносить и растягиваться.

Четвёртое: **контрибьютор должен уметь изменить стиль, не изучая новый язык.** CSS-в-классах и
CSS-в-JS — оба требуют обучения; обычный CSS — нет.

## Решение

**Mantine 7 — единственный UI-kit проекта. Стилизация — CSS Modules (`*.module.css`) поверх
переменных темы Mantine. Tailwind не используется.**

**Работа с Mantine.**

1. **Сначала MCP, потом код.** Перед использованием компонента или хука спрашиваем официальный MCP
   `mantine` (`list_items` / `search_docs` / `get_item_props`) про API текущей версии, а не пишем по
   памяти. Это правило существует потому, что API между минорными версиями меняется, а память
   ассистента и разработчика — нет.
2. **Берём не только компоненты, но и хуки/утилиты**: `useDisclosure`, `useDebouncedValue`,
   `useMediaQuery`, `@mantine/form`, `@mantine/dates`, `@mantine/notifications`, `@mantine/hooks`.
3. **Не оборачиваем ради обёртки.** `Button`, `TextInput`, `Select`, `Menu`, `Tabs`, `Modal`,
   `Drawer`, `Tooltip` используются напрямую. Обёртка в `shared/ui` заводится, только когда есть что
   зафиксировать: поведение (авто-очистка буфера после копирования секрета), политику
   (подтверждение разрушающего действия), состояние (`DataState`: loading/error/empty/content).
4. **Формы — только `@mantine/form` + `mantine-form-zod-resolver`.** Второй формовой библиотеки в
   проекте нет.
5. **Таблицы** — разделение ответственности: `TanStack Table v8` отвечает за модель (колонки,
   сортировка, выделение, виртуализация), Mantine `Table` — за разметку и стили. Не наоборот.
6. **Иконки** — один набор `@tabler/icons-react`, размеры только `16 | 20 | 24`, `stroke={1.5}`.

**Стилизация.**

- Файл `<name>.module.css` рядом с компонентом; подключение через `classNames`/`className`, а не
  через `style` и не через `sx`-подобные инлайны. `style={{ marginTop: 12 }}` — ошибка ревью;
  вместо этого `Stack`/`Group` с токеном отступа.
- **Только CSS-переменные темы**, никаких литеральных цветов и пикселей. Семантические алиасы
  объявляются один раз в `app/styles/tokens.css`:

  ```css
  :root {
    --bc-surface:        light-dark(var(--mantine-color-white), var(--mantine-color-dark-7));
    --bc-surface-raised: light-dark(var(--mantine-color-gray-0), var(--mantine-color-dark-6));
    --bc-border:         light-dark(var(--mantine-color-gray-3), var(--mantine-color-dark-4));
    --bc-text:           light-dark(var(--mantine-color-gray-9), var(--mantine-color-dark-0));
    --bc-text-muted:     light-dark(var(--mantine-color-gray-6), var(--mantine-color-dark-2));
  }
  ```

- **Тёмная тема — не отдельный набор классов**, а `light-dark()` в объявлениях. Переключатель
  `system | light | dark`, по умолчанию `system`.
- `postcss-preset-mantine` даёт миксины и брейкпоинты; шкалы `spacing` и `radius` — только из темы.
- Глобальный CSS — только для действительно глобального (reset, токены) в `app/`.
- Логические свойства (`margin-inline-start`, `inset-inline-end`) вместо `left/right` — чтобы
  будущая поддержка RTL была правкой темы, а не переписыванием стилей.

**Tailwind не подключается.** Если бы проект когда-либо перешёл на Tailwind, обязательным условием
были бы CSS `@layer` (cascade layers) для управления порядком каскада Mantine ↔ Tailwind ↔ app —
но такой переход не планируется и потребовал бы отдельного ADR.

## Альтернативы (и почему отвергнуты)

| Альтернатива | Плюсы | Минусы | Почему отвергнута |
|---|---|---|---|
| **Tailwind + headless-kit (Radix / shadcn-ui)** | Полный контроль над разметкой и стилями; отличная a11y у Radix-примитивов; shadcn даёт код в репозиторий, а не зависимость; очень быстрая итерация по вёрстке; огромное сообщество | Готовых **сложных** компонентов нет: таблица с сортировкой и виртуализацией, датапикер с диапазоном, календарь, комбобокс с асинхронной загрузкой, дровер, нотификации собираются вручную; каждый такой компонент — недели работы и собственный источник a11y-багов; вёрстка в className становится плохо читаемой на плотных экранах; при смешении с любым готовым компонентом начинается война каскадов | Проект — плотное рабочее приложение, где сложные компоненты составляют большую часть UI. Mantine закрывает их из коробки, включая a11y и клавиатуру. Экономия здесь измеряется месяцами, а не днями. Контроль над разметкой, который даёт Tailwind, нам нужен реже, чем готовое поведение |
| **MUI (Material UI)** | Самая полная библиотека компонентов; зрелая, огромная экосистема; отличная документация; сильные data-grid и датапикеры | Material Design — узнаваемый и навязчивый визуальный язык, «уводящий» продукт в сторону Google; глубокая кастомизация темы трудоёмка; Emotion как рантайм CSS-in-JS даёт накладные расходы и усложняет SSR; **лучшие возможности data-grid — в коммерческой X-версии**, несовместимой с AGPL-репозиторием (см. [ADR-0018](0018-license-agpl-3.md)) | Лицензионное ограничение data-grid — блокирующий фактор для open-source-проекта, который любой может форкнуть. Плюс визуальная идентичность и рантайм CSS-in-JS |
| **Chakra UI** | Отличный DX, хорошая a11y, приятная система стилевых пропсов | Стилевые пропсы (`mt={4} bg="gray.100"`) — тот же inline-стиль, только в JSX: невозможно переиспользовать, трудно ревьюить, легко расходится; набор сложных компонентов беднее Mantine (нет полноценных таблиц, дат, богатых нотификаций); v3 сменил модель стилей, экосистема в переходе | Сложных компонентов меньше, а стилевая модель поощряет ровно то, что мы запрещаем (ad-hoc стили в разметке) |
| **styled-components / Emotion поверх headless** | Полная свобода; тематизация в JS; динамические стили от пропсов | Рантайм-генерация стилей стоит производительности на плотных списках; React 19 и Server Components вытесняют рантайм CSS-in-JS; ещё один язык (шаблонные литералы CSS) для контрибьютора; сложнее статически проверить использование токенов | Проигрывает CSS Modules по производительности и по простоте, не давая ничего, чего не дают переменные темы |
| **Vanilla Extract / Panda CSS (zero-runtime CSS-in-TS)** | Типобезопасные токены, нулевой рантайм, отличная DX | Сборочная магия и специфичная интеграция с Vite; ещё одна абстракция поверх CSS; типобезопасность токенов частично достигается линт-правилом на CSS-переменные | Выигрыш не окупает дополнительный слой; CSS Modules — то, что рекомендует автор Mantine, и то, что понятно без обучения |
| **Собственная дизайн-система с нуля** | Полный контроль, идеальное соответствие продукту, отсутствие внешних зависимостей | Годы работы на достижение качества a11y и поведения, которые Mantine даёт сразу; постоянная стоимость поддержки | Несоразмерно ресурсам проекта и не создаёт продуктовой ценности |
| **Mantine, но со стилизацией через `sx`/`style`-пропсы** | Быстрее пишется, всё в одном файле | Стили не переиспользуются, не кешируются браузером, не поддаются поиску и правке дизайнером; тёмная тема требует условной логики в JS вместо `light-dark()` | CSS Modules — рекомендованный автором Mantine путь; он же даёт статически проверяемое использование токенов |

## Последствия

### Положительные

- **Сложные компоненты закрыты из коробки** — таблицы, дроверы, даты, комбобоксы, нотификации,
  ловушка фокуса. Экономия исчисляется месяцами.
- **A11y-база получена бесплатно**: роли, `aria-*`, клавиатурная навигация и управление фокусом
  реализованы в библиотеке и протестированы её сообществом.
- **Один источник стилевой правды.** Тема Mantine → CSS-переменные → всё остальное, включая графики
  и редактор. Смена палитры — правка одного файла темы.
- **Нет войны каскадов.** Единственный UI-kit и CSS Modules с локальными классами — конфликтов
  специфичности нет.
- **Тёмная тема без дублирования** благодаря `light-dark()`.
- **CSS остаётся CSS**: контрибьютор правит стиль, не изучая утилитарный DSL; DevTools показывают
  осмысленные имена классов.
- **Стили кешируются как статика** и не влияют на размер JS-бандла.
- **Длинные русские строки не ломают вёрстку**: компоненты Mantine растягиваются, а правило
  `min-width` вместо `width` закреплено в дизайн-системе.

### Отрицательные / цена

- **Привязка к экосистеме Mantine.** Мажорное обновление библиотеки — событие, требующее прогона
  всего UI. Компонента, которой нет в Mantine, придётся писать самому либо искать совместимую.
- **Потолок кастомизации.** Глубоко переопределить внутреннюю структуру компонента Mantine сложнее,
  чем собрать свой из headless-примитивов. Часть дизайнерских хотелок будет отклонена.
- **Два файла на компонент** (`.component.tsx` + `.module.css`) вместо одного.
- **Динамические стили от данных** (цвет метки, прогресс) требуют CSS-переменных, прокинутых через
  `style`, — единственное разрешённое исключение из запрета инлайнов, и его нужно явно оговаривать.
- **Размер бандла Mantine** ощутим; требуется следить за импортами и code-splitting'ом.
- **Правило «сначала MCP»** замедляет написание кода и требует наличия MCP-сервера в окружении
  разработчика.

### Что становится трудно изменить позже

- **Смена UI-kit — это переписывание всего интерфейса.** Компоненты Mantine используются напрямую
  (мы намеренно не оборачиваем их ради обёртки), поэтому слоя адаптации, за которым можно было бы
  подменить библиотеку, не существует. Это осознанный обмен: обёртки ради теоретической
  заменяемости стоили бы дороже, чем сама замена, вероятность которой мала.
- **Токены темы становятся публичным контрактом стилей.** На `--mantine-*` и `--bc-*` ссылаются
  сотни CSS-модулей, а также темы графиков, редактора документов и календаря. Переименование или
  смена семантики токена — сквозная правка.
- **Отказ от Tailwind фиксирует стилевой язык проекта.** Ввести Tailwind позже можно только с
  `@layer` и полной ревизией каскада; практически это означает два стилевых подхода в одном
  репозитории на неопределённый срок.
- **`@mantine/form` как единственная формовая библиотека** проникает во все формы продукта вместе с
  `mantine-form-zod-resolver`. Переход на react-hook-form — правка каждой формы.
- **Решение «TanStack Table для модели, Mantine для разметки»** определяет структуру всех таблиц
  продукта; смена любой из половин затрагивает все табличные экраны.

## Проверяемость

- **Stylelint-правило на литеральные значения**: цвета (`#rrggbb`, `rgb()`, именованные) и
  пиксельные отступы в `*.module.css` запрещены — только `var(--mantine-*)` / `var(--bc-*)`.
  Нарушение ломает `pnpm lint`.
- **ESLint-правило на inline-стили**: `style={{ ... }}` в компонентах запрещён, кроме явного
  allow-list для CSS-переменных, задаваемых из данных (`style={{ '--bc-progress': value }}`).
- **Тест «нет второго UI-kit»**: проверка `package.json` — отсутствие `@mui/*`, `@chakra-ui/*`,
  `tailwindcss`, `antd`, `styled-components`, `@emotion/styled` в зависимостях клиента.
- **Автотест контраста палитры**: пары «текст на поверхности» из `tokens.css` проверяются на
  WCAG AA программно, в светлой и тёмной теме — а не «глазами».
- **Storybook с псевдолокалью**, удлиняющей строки на 40 %: все компоненты `shared/ui`
  прогоняются на переполнение до появления реального перевода.
- **A11y-тесты**: `@axe-core/playwright` на ключевых экранах в e2e-наборе; нарушения уровня
  critical/serious ломают сборку.
- **Визуальная регрессия** ключевых компонентов `shared/ui` в светлой и тёмной теме.
- **`size-limit` на бандл** — рост от неаккуратных импортов Mantine ловится порогом.
- Гейт-агент `accessibility-expert` (правила проекта) — для историй, добавляющих новые интерактивные
  компоненты.
