# ADR-0011 — Поиск на Meilisearch с учётом прав, с деградацией на Postgres FTS

## Контекст

Глобальный поиск — один из основных способов навигации в Bad CRM: `Cmd+K` ищет по задачам,
документам, заметкам базы знаний, сообщениям чата, файлам, клиентам и контрактам. Требования к нему
формируются тремя обстоятельствами.

**Первое: поиск обязан учитывать права.** Результаты выдачи не могут содержать документы приватного
проекта, в который человек не входит, или сообщения приватного канала. При этом фильтрация
результатов **после** выдачи неприемлема: она ломает релевантность и пагинацию (запросили 20,
отфильтровали 17, осталось 3), а по числу отфильтрованных позиций можно вывести существование
скрытых объектов.

**Второе: содержимое двуязычное (EN/RU) и пользователи ошибаются в наборе.** Поиск «дизан» должен
находить «дизайн», поиск «rls» — находить «RLS» в заголовке архитектурной заметки. Морфология
русского делает наивный поиск по подстроке практически бесполезным.

**Третье: поиск должен быть отключаемым.** Профиль `minimal` рассчитан на 2 vCPU / 2 GB и не
поднимает лишних контейнеров ([ADR-0020](0020-self-host-packaging-docker.md)). Приложение обязано
стартовать и работать без поискового движка — с деградацией функции, а не с отказом.

Дополнительный контекст: лицензионная политика проекта ([ADR-0018](0018-license-agpl-3.md))
запрещает зависимости под SSPL и Elastic License, что исключает современный Elasticsearch.

## Решение

**Meilisearch 1.x (MIT) как основной поисковый движок; `SearchPort` с двумя адаптерами;
permission-aware документы плюс tenant token как второй барьер.**

**Индексируемый документ содержит поля доступа, а не только контент:**

```json
{
  "id": "task_01H...",
  "organizationId": "org_01H...",
  "entityType": "TASK",
  "title": "...",
  "body": "...",
  "projectId": "prj_01H...",
  "updatedAt": 1753500000,
  "visibleTo": ["user:u1", "team:t3", "project:p7", "role:r2"]
}
```

**`visibleTo` — каноническое имя поля** списка принципалов, которым документ доступен. Оно
используется во всех адаптерах, во всех фильтрах и во всей документации; синонимы (`acl`,
`principals`, `allowedTo`) не заводятся.

**Запрос фильтруется по `visibleTo IN [принципалы текущего пользователя]`** — то есть фильтрация
происходит в движке, до формирования выдачи. Релевантность и пагинация остаются корректными, и по
результатам невозможно вывести существование скрытых документов.

**Второй барьер — Meilisearch tenant token**, выпускаемый API с жёстко зашитым фильтром
`organizationId = ...`. Даже ошибка в сборке пользовательского фильтра не выдаст документ чужого
арендатора. Это прямой аналог RLS ([ADR-0004](0004-multi-tenancy-postgres-rls.md)) для поискового
слоя: приложение фильтрует, а токен отсекает то, что приложение пропустило. Мастер-ключ
Meilisearch клиенту не выдаётся никогда.

**Индексация идёт только через outbox** ([ADR-0021](0021-transactional-outbox.md)). Прямых вызовов
индексатора из use-case нет, поэтому ситуация «запись прошла, индекс не обновился» невозможна при
успешной транзакции. **Изменение ACL ресурса тоже порождает событие переиндексации** — иначе
человек, лишённый доступа, продолжал бы находить документ поиском.

**Порт `SearchPort` имеет два адаптера:**

- `meilisearch.adapter.ts` — полный профиль;
- `postgres-fts.adapter.ts` — профиль `minimal`, полнотекстовый поиск Postgres (`tsvector` +
  GIN-индекс, конфигурации словарей для английского и русского).

Профиль выбирается конфигурацией в composition root. **Контракт порта и permission-фильтрация
одинаковы для обоих**: адаптер Postgres применяет тот же фильтр по принципалам, только средствами
SQL, и работает внутри `withTenant`, где действует RLS.

**Поисковый индекс — производное состояние.** Его можно удалить и восстановить переигрыванием из
БД. Отсюда следствие в развёртывании: том `meili-data` **не бэкапится**, а переход
`minimal → full` — это поднять контейнер и запустить полную переиндексацию, без миграции данных.

**Содержимое E2EE-хранилища в индекс не попадает вообще** — сервер его не видит; поиск по секретам
реализован blind index'ом на клиенте ([ADR-0009](0009-e2ee-vault-key-hierarchy.md)).

## Альтернативы (и почему отвергнуты)

| Альтернатива | Плюсы | Минусы | Почему отвергнута |
|---|---|---|---|
| **Только Postgres FTS** | Ноль дополнительных контейнеров; транзакционная консистентность индекса с данными (индексируем в той же транзакции — нет рассинхронизации вообще); фильтрация по правам средствами SQL и RLS; бесплатно с точки зрения эксплуатации | Нет typo-tolerance: «дизан» не найдёт «дизайн»; ранжирование `ts_rank` заметно грубее; нет мгновенного search-as-you-type на больших объёмах; поддержка двух языков требует ручного выбора конфигурации словаря на документ; нет фасетов и подсветки из коробки | Как **основной** поиск даёт заметно худший продуктовый опыт: опечатки и морфология — норма при работе с двуязычным контентом. Но как **деградация** это правильный выбор, и именно поэтому адаптер существует и поддерживается, а не является заглушкой |
| **Elasticsearch / OpenSearch** | Самый мощный движок: агрегации, сложные анализаторы, морфология, синонимы, «более похожие»; document-level security в коммерческих сборках; огромная экосистема | Гигабайты RAM на self-host инстансе — несовместимо с профилем 2 GB; сложная эксплуатация (шарды, реплики, heap); **Elasticsearch распространяется под SSPL/Elastic License**, что прямо запрещено политикой лицензий проекта; OpenSearch (Apache-2.0) лицензионно подходит, но ресурсные требования те же | Ресурсы и лицензия. Даже OpenSearch превратил бы «запустить одной командой» в «выделить под поиск отдельный сервер» |
| **Typesense** | Очень близкий аналог Meilisearch: typo-tolerance, быстрый, GPL-3.0 (совместим с AGPL); есть встроенные scoped API keys с фильтрами; хорошая документация | Меньше сообщества и материалов; чуть выше потребление памяти на сопоставимых объёмах; функционально паритетен, то есть не даёт причины для смены | Близкий второй вариант. Meilisearch выбран по совокупности: MIT (максимально мягкая лицензия для нашей allow-list), меньший расход RAM, более простая эксплуатация. Решение не является принципиальным — порт позволяет добавить адаптер |
| **pgvector-only семантический поиск** | Уже есть для RAG; понимает смысл, а не только слова | Плохо ищет по точным идентификаторам (`TASK-142`, имя файла, ключ) — то есть по самому частому запросу в рабочем инструменте; требует эмбеддинга каждого запроса, а значит AI-провайдера, который в `minimal` отсутствует | Дополняет полнотекстовый поиск в AI-сценариях, но не заменяет его. Используется в RAG ([ADR-0014](0014-ai-provider-abstraction.md)) |
| **Фильтрация результатов после выдачи** (post-filtering) | Тривиально реализуется; не требует хранить права в индексе; изменение ACL не требует переиндексации | Ломает пагинацию и релевантность; по числу «пропавших» позиций выводится существование скрытых документов; чтобы набрать 20 видимых результатов, приходится запрашивать неизвестно сколько | Утечка через побочный канал плюс сломанный UX. Права обязаны быть в индексе |
| **Индексация напрямую из use-case** (без outbox) | Проще, меньше движущихся частей, событие доходит мгновенно | Классический dual-write: транзакция БД зафиксировалась, вызов индексатора упал — данные и индекс разошлись без следа; откат транзакции после успешной индексации — тоже расхождение | Отвергнуто по тем же причинам, что и в [ADR-0021](0021-transactional-outbox.md) |
| **Внешний поисковый SaaS (Algolia и т. п.)** | Отличное качество и ноль эксплуатации | Передача содержимого документов третьей стороне — неприемлемо для self-hosted продукта; платно; не работает без интернета | Противоречие модели поставки |

## Последствия

### Положительные

- **Опечатки и морфология работают из коробки** — продуктовый поиск ощущается «умным» без ручной
  настройки анализаторов.
- **Права учитываются в движке**, поэтому релевантность и пагинация корректны, а существование
  скрытых документов не выводится.
- **Два независимых барьера изоляции**: фильтр по `visibleTo` и tenant token с зашитым
  `organizationId`.
- **Профиль `minimal` полноценно работает** — не «поиск отключён», а поиск попроще.
- **Индекс не требует бэкапа** и восстанавливается переигрыванием из БД; это упрощает и
  эксплуатацию, и восстановление после аварии.
- **Индексация не может «потеряться»** — она следствие outbox-события, а не отдельного вызова.
- **Изменение прав отражается в поиске** — переиндексация по событию изменения ACL.
- **Смена движка локализована** в одном адаптере: `SearchPort` уже имеет две реализации, значит
  контракт проверен практикой, а не гипотезой.

### Отрицательные / цена

- **Индекс — производное состояние с задержкой.** Между коммитом и появлением документа в поиске
  проходит время обработки outbox. Пользователь может не найти только что созданную задачу.
- **`visibleTo` дублирует модель прав** в денормализованном виде. Расхождение между индексом и
  реальными правами — отдельный класс багов, требующий сверочного джоба.
- **Изменение ACL на верхнем уровне вызывает лавину переиндексации**: смена доступа к проекту
  затрагивает все его задачи, документы и файлы. Требует пакетной обработки и защиты от
  перегрузки очереди.
- **Два адаптера — двойное тестирование.** Каждый поисковый сценарий должен быть проверен в обеих
  реализациях, иначе `minimal` тихо деградирует до неработающего.
- **Разное качество выдачи в профилях** — пользователи `minimal` и `full` видят разные результаты
  по одному запросу. Это нужно объяснять в документации.
- **Ещё один контейнер и ещё один секрет** (мастер-ключ Meilisearch) в полном профиле.
- **Meilisearch не имеет встроенной аутентификации на уровне документа** — безопасность целиком
  на нашей схеме `visibleTo` + tenant token, то есть на нашем коде.

### Что становится трудно изменить позже

- **Схема поискового документа, и особенно имя поля `visibleTo`**, становится контрактом между
  индексатором, всеми адаптерами, фильтрами запросов и документацией. Переименование — сквозная
  правка плюс полная переиндексация на каждой инсталляции.
- **Формат принципалов** (`user:*`, `team:*`, `project:*`, `role:*`) должен совпадать с формой
  принципалов в модели прав ([ADR-0008](0008-permission-model-rbac-plus-acl.md)). Изменение
  формата в одном месте молча ломает фильтрацию в другом: запрос отработает и вернёт пусто или,
  что хуже, лишнее.
- **Контракт `SearchPort`** ограничен пересечением возможностей двух движков. Использование
  специфичной функции Meilisearch (например, фасетов особого вида) немедленно ломает паритет с
  Postgres FTS и профиль `minimal`.
- **Решение «индексация только через outbox»** зашивается во все use-cases, порождающие
  индексируемые сущности. Прямой вызов индексатора, добавленный однажды «для скорости», создаёт
  необнаружимое расхождение.
- **Обещание «индекс не бэкапится»** попадает в runbook и в инструкции по восстановлению. Если
  когда-либо в индексе окажутся данные, которых нет в БД, это обещание станет ложным, а процедура
  восстановления — разрушительной.

## Проверяемость

- **Permission-тест поиска (обязательный)**: пользователь без доступа к приватному проекту не
  получает его задачи и документы ни при каком запросе. Прогоняется **на обоих адаптерах** одним
  набором тестов через контракт `SearchPort`.
- **Тест tenant token**: токен, выпущенный для организации A, не возвращает документы организации B
  даже при намеренно испорченном пользовательском фильтре. Проверяется на реальном Meilisearch
  (Testcontainers).
- **Тест паритета адаптеров**: один и тот же набор сценариев (фильтрация по правам, по типу
  сущности, по проекту, пагинация) выполняется для `meilisearch` и `postgres-fts`; расхождение в
  видимости результатов — падение.
- **Тест «мастер-ключ не покидает сервер»**: проверка, что клиентский бандл и ответы API не содержат
  мастер-ключа; клиенту выдаётся только tenant token с ограниченным TTL.
- **Тест переиндексации по изменению ACL**: снятие доступа порождает outbox-событие, после
  обработки которого документ исчезает из выдачи для этого пользователя.
- **Сверочный джоб «индекс ↔ БД»**: периодически сравнивает количество и контрольные суммы
  документов по типам сущностей; расхождение — метрика и алерт, а не тихая коррекция.
- **Тест восстановления индекса**: полная переиндексация из пустого состояния воспроизводит выдачу
  — подтверждает, что индекс действительно производное состояние и не нуждается в бэкапе.
- **Тест старта без Meilisearch**: приложение поднимается в профиле `minimal`, `SearchPort`
  резолвится в Postgres FTS, поисковые эндпоинты отвечают, health-check зелёный.
- Гейт-агент `security-auditor` (правила проекта) — обязателен для изменений в схеме индексируемого
  документа и в сборке фильтров.
