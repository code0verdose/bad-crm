# Фаза 0 — спецификация, эпики и правила проекта Bad CRM

## Простым языком

1. **Сняли неопределённость до кода.** Провёл два раунда вопросов и зафиксировал восемь развилок, которые нельзя менять потом без переписывания: мульти-тенантность, шифрование паролей, транспорт realtime, поиск, лицензия, backend-стек, AI-провайдеры, файловое хранилище. Зачем: 18 продуктовых доменов без этих решений гарантированно приводят к переделке фундамента через пару месяцев.

2. **Написали продуктовые документы.** PRD с персонами, MoSCoW-скоупом, 18 рисками и таблицей трассируемости «пункт ТЗ → эпик», дорожную карту на девять этапов и глоссарий на 133 термина. Зачем: глоссарий — это ubiquitous language, из него берутся имена таблиц и папок, чтобы одна сущность не называлась в трёх местах по-разному.

3. **Спроектировали систему.** C4-обзор, доменная модель на ~100 сущностей, документ по стеку, UX-архитектура с полной картой маршрутов. Зачем: чтобы разработчик не изобретал структуру заново на каждом эпике.

4. **Отдельно проработали три самых опасных места** — изоляцию арендаторов, модель прав и шифрование секретов. Зачем: ошибка в любом из них означает утечку данных, а не баг, который чинится патчем.

5. **Разбили работу на 46 эпиков по девяти этапам** и расписали первые два этапа на 113 историй с проверяемыми критериями. Зачем: этапность выстроена так, что каждый следующий опирается на готовый фундамент, а самое рискованное (шифрование) не блокирует ранний релиз.

6. **Записали правила разработки и завели девять проверяющих агентов.** Зачем: правила и агенты ловят нарушения инвариантов автоматически, а не на код-ревью через месяц.

7. **Прогнали три волны сверки.** Судьи нашли и устранили 20 + 13 + 3 расхождения между документами — от лицензионного блокера до дрейфа названий криптопримитивов. Зачем: параллельные агенты неизбежно расходятся в деталях, и без сверки это всплывает уже в коде.

## Технически

1. **Discovery (2 раунда `AskUserQuestion`)** — зафиксировано: pnpm + turborepo монорепо; **Express 5** + Prisma + PostgreSQL 16 (+pgvector), гексагональная архитектура; **multi-tenant с RLS** с первого дня; **E2EE zero-knowledge** vault; Socket.IO + `@socket.io/redis-streams-adapter`; Meilisearch отдельным сервисом; S3/MinIO; AI-провайдеры настраиваются админом в UI (модель скопирована с `broke`); **AGPL-3.0**.

2. **`docs/product/`** — `prd.md` (5 персон, MoSCoW, NFR с числами, R-01…R-18, таблица трассируемости 18 пунктов ТЗ), `roadmap.md` (M1…M9 + milestone gates), `glossary.md` (133 термина, колонка `Unit / Entity`).

3. **`docs/architecture/`** — `overview.md` (C4 L1–L3, 14 ограниченных контекстов, 9 mermaid-диаграмм), `data-model.md` (~100 сущностей в 15 группах, метки `[T]`/`[G]`, 15 ER-диаграмм, индексы, стратегия миграций), `stack.md` (13 разделов, `withTenant`/`guardedClient`, outbox с `FOR UPDATE SKIP LOCKED`), `ux-architecture.md` (карта маршрутов, 12 ключевых экранов, дизайн-система), `adr/0001…0021`.

4. **`docs/security/`** — `permission-model.md` (318 ключей, 102 опасных; пятислойная модель; алгоритм `deny > allow > role > default`; permission-matrix snapshot-тест), `rls-design.md` (роли `app_user`/`app_migrator`/`app_auth`, `USING` + `WITH CHECK` + `FORCE`, три особых пути, параметризованный шаблон isolation-теста), `e2ee-design.md` (Argon2id → MUK → keypair → vault key → item key, 15 mermaid-диаграмм жизненного цикла, blind index, остаточные риски), `threat-model.md` (102 угрозы `T-<контекст>-<номер>`, 8 профилей нарушителя, `RR-01…07`).

5. **`epics/`** — 46 `epic.md` с frontmatter (`id/status/blocked/milestone/owner/created`), 113 историй `STORY-NNN-XX` с Given/When/Then и DoD, включающим шесть проверок гейта; борд `epics/README.md` генерируется `~/.claude/skills/pm/sync-board.sh`.

6. **`rules/` — 34 файла `.mdc`**, из них 23 покрывают имена, на которые уже ссылались истории (проверено grep-ом). Критичные: `tenancy-rls`, `permissions`, `e2ee-crypto`, `hexagonal-backend`, `api-contract`, `db-migrations`.

7. **`.claude/agents/` — 9 read-only агентов**: `tenancy-rls-auditor`, `permission-matrix-auditor`, `e2ee-crypto-reviewer`, `openapi-contract-guardian`, `fsd-architecture-linter`, `realtime-event-reviewer`, `search-permission-auditor`, `i18n-coverage-checker`, `selfhost-upgrade-checker`.

8. **Оркестрация** — 4 волны по ≤5 агентов, после каждой агент-судья (`architect-review`, `code-reviewer`, `general-purpose`). Судьи устранили: битую нумерацию эпиков в `overview.md`, параллельную нумерацию ADR в `stack.md`, лексику sales-CRM (`deal`→`task`, ~45 замен), два формата ключей прав (`task.write` → `task:update`), расхождение `User`/`Employee`/`EmployeeProfile`, дрейф криптопримитивов (WebCrypto AES-GCM → libsodium) в четырёх документах.

9. **Лицензионный блокер, найденный при ревью:** premium-плагины `@schedule-x/*` (event modal, drag-to-create, resource view) распространяются по платной проприетарной лицензии и несовместимы с AGPL-дистрибуцией — UX опирался именно на них. Зафиксирован запрет в пяти местах, создание события переведено на собственную Mantine-модалку. Проверены также BlockNote (ядро MPL-2.0 — ок, `@blocknote/xl-*` под GPL-3.0 — совместимо, фиксировать в ADR-0012) и `libsodium-wrappers-sumo` (ISC, исключение по размеру бандла узаконено).

10. **Решения пользователя, применённые к документам:** Express 5 вместо 4; libsodium вместо `@noble/*`; сторно времени записью в той же таблице (`TimeEntry.reversesId`, CHECK ослаблен до `<> 0`); сущности дашбордов и онбординга дописаны в модель; три права вне скоупа 1.0 удалены.

11. **Решения, принятые самостоятельно по рекомендации судьи:** имена units в **единственном** числе (совпадают с именем Prisma-модели, как в `broke`) с переносом правила в `rules/naming-and-structure.mdc`; вкладке материалов добавлены маршруты `/materials`, `/materials/$slug`, `/admin/materials`; колонка `UserKeyPair.orgEscrowBlobEnc` удалена, депонирование MUK запрещено правилом `e2ee-crypto.mdc` п.8.

12. **Итог:** 256 файлов, 38 796 строк markdown, 0 строк кода. Проверено скриптом: нумерация `EPIC-001…046` без пропусков, 113 историй с валидным frontmatter, битых относительных ссылок нет (кроме `docs/api/openapi.yaml`, создаётся в STORY-003-05).

## Применённые технологии

- [[PostgreSQL]] — Row Level Security как рубеж изоляции арендаторов, pgvector под RAG, партиционирование аудита и сообщений.
- [[Prisma]] — `$extends`-обёртка `withTenant`, выставляющая `app.organization_id` внутри транзакции.
- [[Express]] — версия 5.x: async-хендлеры пробрасывают отклонённые промисы в error-handler без `asyncHandler`.
- [[React]], [[Mantine]], [[TanStack Query]], [[TanStack Router]], [[Zod]], [[TypeScript]] — канонический фронтенд-стек, FSD «units».
- [[Meilisearch]] — permission-aware поиск через tenant tokens с обязательным фильтром.
- [[Socket.IO]] — realtime с redis-streams-adapter, комнаты `org:{id}:{resource}:{id}`.
- [[libsodium]] — Argon2id, XChaCha20-Poly1305, `crypto_box_seal`, Ed25519 для E2EE-хранилища.
- [[BullMQ]], [[Redis]], [[MinIO]], [[Docker]] — очереди и outbox, кеш и presence, S3-хранилище, self-host упаковка.
