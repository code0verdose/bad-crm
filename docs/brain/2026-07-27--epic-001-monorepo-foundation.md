# EPIC-001 — фундамент монорепо и dev-окружение

Сводная запись по эпику. Технические разборы отдельных проблем — в соседних записях:
[[2026-07-27--gate-blockers-cache-lint-coverage]] (кеш turbo, линт, покрытие),
[[2026-07-27--restore-grants-partitions]] (восстановление БД, гранты, партиции).

## Простым языком

1. **Собрал каркас проекта из четырёх пакетов** — клиент, сервер, общий код и e2e — так, чтобы они не могли случайно зависеть друг от друга не в ту сторону. Зачем: направление зависимостей потом не переделать, а нарушенное оно превращает монорепо в один большой ком.

2. **Настроил линтер так, чтобы он стерёг архитектуру, а не только стиль.** Он запрещает обращаться к базе мимо слоя доступа к данным, импортировать вглубь чужого модуля, класть запросы в страницы. Зачем: правила, записанные только в документе, не соблюдаются — их должна проверять машина.

3. **Поднял локальное окружение одной командой** — база, кеш, файловое хранилище, поиск и почтовая ловушка. Все порты закрыты снаружи, версии зафиксированы, паролей в файле нет. Зачем: разработчик должен получить рабочую систему после `git clone`, а не собирать её вручную.

4. **Описал все переменные окружения схемой, которая проверяется при старте.** Приложение отказывается запускаться на публичных плейсхолдерах и без TLS — везде, кроме локальной разработки. Зачем: типовая утечка self-host — инсталляция, запущенная на пароле из публичного репозитория.

5. **Наполнил общий пакет** примитивами проверки данных, типизированными идентификаторами и заготовкой каталога прав. Зачем: одна сущность должна называться одинаково на сервере и клиенте, а идентификаторы разных сущностей нельзя путать между собой.

6. **Прогнал шесть проверок гейта — четыре круга.** Гейт трижды был красным и трижды нашёл то, что не видно в тестах: запрещённую лицензию, кеш, отключавший единственную проверку, и нерабочую процедуру восстановления БД. Зачем: именно ради этого гейт и существует.

## Технически

1. **Монорепо**: pnpm workspaces + turborepo, `packages/{client,server,shared,e2e}`; `dependsOn: ["^build"]`, раздельные `typecheck`/`build`, `persistent` для `dev`. Направление зависимостей (`client → shared`, `server → shared`, `shared → ∅`, `e2e → ∅`) зафиксировано в `package.json`, проверяется тестом и ESLint-запретом.

2. **TypeScript** — `tsconfig.base.json` strict + `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, project references; сервер `NodeNext` + `@/*` через `tsc-alias`; `shared` без `DOM` и `@types/node` (изоморфность проверяется тестом с положительным контролем). Версия зафиксирована **5.9.3 на весь воркспейс** — [ADR-0022](../architecture/adr/0022-typescript-version-policy.md): TS 7 не экспортирует классический compiler API, `typescript-eslint` объявляет peer `<6.1.0`, а две версии компилятора для сборки и линта — ловушка.

3. **ESLint 9 flat** (`eslint.config.js` + локальный плагин `bad-crm/require-role-suffix`): границы пакетов, слои гексагона (`domain` без I/O, `application` без адаптеров), запрет `@prisma/client` вне `infrastructure/persistence`, слои FSD, запрет `useQuery`/`fetch` в `pages`/`widgets`/`app`, kebab-case + role-suffix, `no-default-export`, type-aware правила. Каждое правило покрыто негативной фикстурой **и положительным контролем** (`test/lint/architecture-rules.test.ts`) — иначе неподключённый конфиг молчит и тест зелёный.

4. **docker-compose** — `pgvector/pgvector:0.8.5-pg16`, `redis:8.8.1-alpine`, MinIO + one-shot init бакета, Meilisearch, Mailpit. Все порты на `127.0.0.1`, теги зафиксированы, healthcheck у каждого сервиса, профили `minimal`/`default`. **Redis только 8.x** — 7.4 распространяется по RSALv2/SSPLv1, обе запрещены при AGPL-3.0; регрессию ловит тест по мажору образа.

5. **Env** — `.env.example` + zod-схемы отдельно для сервера и клиента; parity-тест сверяет шаблон со схемами и с `${VAR}` из compose в обе стороны. Preflight отвергает плейсхолдеры и `http://` **на всём, что не `development`** (T-SH-01/T-SH-03) — исходно был привязан к `production`, что оставляло дыру для `NODE_ENV=test`. Серверные секреты не попадают в клиентскую схему, это доказано тестом.

6. **`packages/shared`** — zod-примитивы (email, пароль, пагинация, money в целых micro-единицах, slug, timezone), branded id через `.brand<…>()`, коды ошибок для `application/problem+json`, заготовка каталога permissions с чистой `can()` (конъюнкция capability и ACL, fail-closed на всех ветках).

7. **Роли БД раньше плана**: `app_migrator` / `app_user` / `app_auth` / `backup_role` создаются идемпотентным bootstrap. Владелец нужен до первой миграции, а `initdb.d` отрабатывает только на пустом томе. Ключевой инвариант — атрибуты переутверждаются **на каждом прогоне**: иначе переиспользуемый кластер оставляет `app_user` с `INHERIT` и членством в `app_migrator` при формально успешном bootstrap.

8. **Итог гейта (4 круга):** `scan-secrets` 🟢 · `scan-cruft` 🟡 WARN (плейсхолдеры в `.env.example` и тестах) · `test-coverage` 🟡 → покрытие включено с порогами `rules/testing.mdc` §7 · `security-auditor` 🟢 PASS · `db-reviewer` 🟡 WARN, блокирующего нет · `production-readiness` 🔴×3 → 🟢 · `commit-hygiene` 🟢 PASS. Коммит `1fdf80d`, 164 файла, 277 тестов уровня репозитория + 248 в пакетах.

## Применённые технологии

- [[TypeScript]] — strict + project references, единая версия на воркспейс.
- [[Node.js]] — 22.22.1 (флор поднят под `lint-staged`/`commitlint`).
- [[Docker]] — dev-стек, профили, healthcheck по TCP (сокетная проба зеленеет до создания ролей).
- [[PostgreSQL]] — роли под RLS, расширения, bootstrap и гранты обходом каталога.
- [[Redis]] — 8.x, лицензионное ограничение AGPL.
- [[MinIO]], [[Meilisearch]] — опциональные сервисы, деградация через feature-flag.
- [[Zod]] — schema-first валидация окружения, `z.coerce` для строк из шелла.
