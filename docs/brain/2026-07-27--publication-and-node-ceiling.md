# Публикация репозитория и потолок версии Node, выключивший обновления зависимостей

## Простым языком

1. **Залил проект на GitHub, не выполняя инструкцию GitHub буквально.** Стандартный сниппет «создай новый репозиторий» начинается с `git init` и `git commit -m "first commit"` — на существующем проекте это уничтожило бы историю из семи коммитов и затёрло настоящий README. Нужны были только две последние строки: добавить remote и запушить.

2. **Перед публикацией проверил, что уходит наружу.** Сканер секретов по всей истории — чисто, `.env` в git не попадал. Репозиторий становится публичным один раз; отозвать это нельзя.

3. **Заменил заглушки, но не выдумал контакты.** `<org>` в командах клонирования и в ссылке на исходники (её требует лицензия) заменил на реальный адрес. А вот два плейсхолдер-адреса почты **не стал** заменять выдуманными: опубликованный адрес, который отбивает письма, говорит человеку, что его сообщение принято, когда оно не принято. Документы теперь называют только работающий канал и прямо пишут, что почтового нет.

4. **Первый живой запуск CI показал упавшую задачу Dependabot** — и это оказалась не мелочь. Механизм, который должен присылать обновления безопасности, был выключен целиком: он запускается на Node 24, а мы объявили, что поддерживаем только Node 22. Каждая зависимость отвечала «версия инструмента не поддерживается», ни одно обновление не могло даже открыть pull request.

5. **Причина — строчка, которую я сам написал и не проверил.** Верхняя граница «ниже 23» не была ничем измерена. Прогнал весь набор тестов на Node 24 — 501 тест прошёл, падала **только сама проверка диапазона**. Потолок убрал.

6. **Утверждение, которое пришло на смену, не осталось декларацией.** Раз мы теперь говорим «работаем на любом Node выше нижней границы», это должно проверяться. Добавил в CI отдельную задачу, которая гоняет весь набор на самом свежем поддерживаемом Node — но не на каждом pull request, а на ветке `main` и раз в неделю: сигнал меняется со скоростью релизов Node, а не коммитов.

## Технически

1. **Публикация.** `git remote add origin` + `git push -u origin main` — 7 коммитов на `origin/main`. Инструкции GitHub (`git init`, `echo "# bad-crm" >> README.md`, `git commit -m "first commit"`) не выполнялись: они рассчитаны на пустой каталог. Перед пушем: `gitleaks git . --log-opts "--all"` → clean, `git ls-files | grep '^\.env'` → только `.env.example`.

2. **Заглушки.** `<org>` → `code0verdose` в README/README.ru/CONTRIBUTING/`install.md`/`ISSUE_TEMPLATE/config.yml`; `NOTICE` получил реальный `Source code:` (требование AGPL §13); issue-чузер теперь ведёт прямо на форму приватного репорта, а ссылка на документацию оставлена вторым пунктом — на случай, когда private vulnerability reporting ещё не включён и форма отдаёт 404. `SECURITY.md` и `CODE_OF_CONDUCT.md`: плейсхолдеры удалены, каналы описаны честно.

3. **Диагноз Dependabot.** Лог доступен только авторизованно (`gh auth login`), поэтому до авторизации я отказался гадать и править конфиг вслепую. По логу:
   ```
   | typescript | tool_version_not_supported | { "tool-name": "Node",
   |            |                            |   "detected-version": ">=22.22.1 <23",
   |            |                            |   "supported-versions": "v24.18.0" }
   ```
   — и так по каждому пакету. Причина: `engines.node` в корневом `package.json` + `engine-strict=true` в `.npmrc`.

4. **Измерение перед правкой.** `nvm use 24` + полный прогон: `pnpm run test:repo` → 501 passed. Через turbo падало только `//#lint:repo` с `ERR_PNPM_UNSUPPORTED_ENGINE` — то есть проверка диапазона, а не код. Это и есть доказательство, что потолок был ничем не подкреплён.

5. **Правка.** `engines.node`: `">=22.22.1 <23"` → `">=22.22.1"`. Два теста, утверждавших обратное (`toolchain-versions.test.ts` — «stays inside the Node 22 LTS line», `workspace-layout.test.ts` — «requires Node 22»), переписаны на противоположный инвариант: **потолка быть не должно**, и в докстринге записано, почему. `.nvmrc` не тронут — он про то, на чём работают контрибьютор и CI.

6. **Джоба `compat`.** `if: github.event_name != 'pull_request'`, матрица `node: ['24']`, `pnpm install --frozen-lockfile` **с включённым** `engine-strict` (отказ установки — ровно тот отказ, который джоба обязана показывать), затем полный набор. Триггер `schedule: '17 6 * * 1'` добавлен в workflow, а `checks` и `scan` получили `if: github.event_name != 'schedule'` — перезапуск того же коммита раз в неделю ничего не доказывает.

7. **Тесты workflow пришлось уточнить, а не отключить.** Джоба `compat` намеренно нарушает три инварианта, написанных для остальных: она дублирует список turbo-задач (сравнение переведено на множества), берёт версию Node не из `.nvmrc` (исключение названо явно, плюс новый тест требует, чтобы у неё была матрица), и упоминала бы версию текстом (формулировка комментария изменена).

8. **Проверено на GitHub:** CI, License check, CodeQL — success; джоба `newest supported Node (24)` — success. Итог правки Dependabot подтвердится на следующем плановом прогоне апдейтера.
