# Дата-слой клиента: один refresh на пачку 401 и срок годности у исключения

STORY-004-04 и STORY-004-06. Продолжение [[2026-07-28--client-foundation-and-csp-in-a-browser]].

## Простым языком

1. **Кеш запросов настроен один раз и по нормативу**, а не «как удобно в этом хуке»: сколько раз повторять, сколько считать данные свежими, что делать при ошибке мутации.

2. **Ключи кеша — типизированная фабрика.** Массив, собранный руками прямо в хуке, теперь роняет проверку. Это не педантизм: инвалидация после мутации работает по ключам, и один разошедшийся ключ означает данные, которые не обновятся, — а увидит это пользователь, не тест.

3. **Откат оптимистичного обновления возвращает список в точности прежним.** Удалённый элемент встаёт **на своё место**, а не в конец — это отдельный тест, потому что «вернули в список» и «вернули как было» выглядят одинаково, пока элемент не был вторым из трёх.

4. **Пачка одновременных 401 вызывает ровно одно обновление токена.** Три параллельных запроса, один общий промис, три повтора. Без этого каждый запрос пошёл бы обновлять токен сам, и сервер увидел бы три ротации подряд — а это уже похоже на кражу токена, и хорошая реализация refresh-семейства на такое отвечает разлогином всей сессии.

5. **Токен живёт только в памяти.** Не в `localStorage`, не в cookie, доступной скриптам. Это инвариант проекта, и его стережёт отдельное правило линтера.

6. **У единственного исключения из правил появился срок годности.** Обновление токена пока идёт «сырым» запросом мимо типизированного клиента — просто потому, что такой операции ещё нет в контракте API. Причина честная, но исключение без срока — это правило, которое никто не соблюдает. Поэтому написан тест, который **упадёт в тот день, когда операция появится в контракте**, и скажет, что заменить.

## Технически

1. **`createAppQueryClient({ notify, logError })`** — `retry: 1`, `staleTime: 30_000`, глобальный `MutationCache.onError`. Локальный `onError` **переопределяет** глобальный, а не добавляется: иначе на одно действие приходит два тоста (`rules/errors-and-toasts.mdc`). `AbortError` не считается ошибкой нигде.

2. **Порт уведомлений вместо прямой зависимости.** `MutationCache.onError` не знает ни о Mantine, ни о i18n — он зовёт `notify.error({ id, messageKey })`, где `messageKey` всегда `errors.<code>`, никогда текст. Реализация-заглушка `silentNotifications` честно ничего не делает и используется тестами; обёртку над нотификациями подставит слой `app/`. `id` содержит ключ, поэтому повтор той же ошибки обновляет тост, а не плодит стопку.

3. **Транспорт** — `openapi-fetch` + `openapi-react-query` поверх типов из контракта. Auth-middleware: Bearer из памяти, при 401 — общий `refreshInFlight`-промис, ровно один повтор, помеченный заголовком, две независимые защиты от петли. Провал refresh → событие в шину, не вызов роутера: транспорт про роутер не знает.

4. **Доказательства мутациями, а не рассуждением.** Убран общий промис — тест падает с `expected 3 to be 1`. Переставлены местами middleware — падает тест про идемпотентный ключ на реплее. Оба вывода приведены в отчёте агента.

5. **Порядок middleware не вкусовой.** Идемпотентность регистрируется раньше auth: ключ должен быть проставлен до того, как запрос уйдёт первый раз, иначе повтор после refresh придёт с другим ключом и сервер посчитает его новым действием.

## Что из этого следует

**Исключение без срока годности — это отменённое правило.** Причина «в контракте пока нет такой
операции» верна ровно до дня, когда операция появится, и никто в этот день не вспомнит. Тест,
падающий на публикации операции, стоит десять строк и снимает вопрос навсегда.

Второе: **глоссарий разошёлся с кодом и с гейтом**. Он отдавал обновление токена `units/session`,
а история и правило линтера — `units/auth`. Разведено явно: механика в `auth`, состояние вкладки в
`session`, с записанным условием слияния в EPIC-006. Расхождение поднял агент, а не ревью — это
правильный порядок.

## Применённые технологии

- [[TanStack Query]] — кеш, инвалидация по фабрике ключей, оптимистичные обновления с откатом.
- [[openapi-fetch]] — типизированный транспорт: несуществующий путь не компилируется.
- [[TypeScript]], [[Vitest]] — типобезопасность ключей и мутационные проверки middleware.
