# Что обещали комментарии

Запись не про фичу, а про коммит-гейт, который её не пустил. Пять агентов, судья, три раунда — и
самый тяжёлый дефект дельты не нашёл никто из пятерых.

## Простым языком

1. **Приём приглашения с командой падал всегда.** Не иногда, не при гонке — на каждом вызове. Тест
   на это был, зелёный, и он сравнивал **текст SQL-запроса** со строкой `'ON CONFLICT'`. Запрос,
   который PostgreSQL отказывается разобрать, такую проверку проходит идеально.
2. **Право видеть зарплату отдавало всю кадровую половину.** Уровни доступа были написаны лестницей
   «публично → персонально → финансы», а все читатели спрашивали «не публично ли?». Встроенная роль
   `manager` держит именно финансовое право и **не** держит персонального.
3. **Опечатка в дате увольнения отвечала 500.** Из четырёх ограничений таблицы три были продублированы
   в приложении, четвёртое — нет, и база отвечала кодом, которого нет в каталоге ошибок.
4. Три из четырёх блокеров — места, где **комментарий утверждал свойство, которого код не имел**.
   Проверка утверждений в комментариях против кода оказалась продуктивнее любой из пяти тематических
   проверок.

## Технически

### Блокер, которого не увидели пять специализированных агентов

`ON CONFLICT ON CONSTRAINT uq_team_members` — а `uq_team_members` создан как `CREATE UNIQUE INDEX`
(именно это генерирует `@@unique` в Prisma). `ON CONFLICT ON CONSTRAINT` резолвится по
`pg_constraint` **на этапе разбора**, где индекса нет. Отсюда `42704` на каждом вызове, а не при
конфликте.

Нашёл его судья — тот, кому досталась задача «сверь показания», а не «проверь свою тему». Пять
тематических агентов прошли мимо: покрытие видело зелёный тест, безопасность — корректную
параметризацию, база — корректную политику RLS.

**Урок про инструмент, а не про людей.** Записанный драйвер не отличает валидный оператор от
невалидного, поэтому любой ассерт вида `expect(sql).toContain(…)` над raw SQL — это проверка того,
что строка написана, а не того, что она работает. В том же файле нашёлся второй такой оператор,
`accept()`, несущий гарантию однократности приглашения: те же подстроки, тот же записанный драйвер,
ни одного исполнения против живой базы. Дефекта в нём не было — но гарантию давал разбор глазами, а
не прогон.

Оба теперь исполняются на реальном PostgreSQL. Заодно выяснилось, что заведомо просроченное
приглашение **вставить нельзя** — `ck_invitations_expiry` отвергает, — так что предикат
`expires_at > $now` пришлось проверять сдвигом момента приёма. База сама сказала то же, что и тест.

### Лестница, которая была расширением прав

```ts
// было
if (view_cost_rate) return 'cost';
if (self || view_personal_data) return 'personal';
return 'public';
// и у всех потребителей: if (visibility !== 'public') → отдать кадровую половину
```

Три уровня выражают порядок, которого в модели прав нет: `admin` держит `view_personal_data` без
`view_cost_rate`, `manager` — наоборот. Ни одно не следует из другого **ни в какую сторону**, и
лестница такое выразить не может по построению.

Заменено на пару булевых. Проверка после починки показала, что `audience.cost` теперь не читает
**ни один** потребитель — то есть «принадлежу какой-то аудитории» стало технически невыразимым.

**И худшее место записи — мои же тесты.** Ассерт `profileVisibility(cost-only) === 'cost'` верен и
бесполезен: значение правильное, а решение принимали потребители. Тесты сериализаторов проверяли
отсутствие ключей с префиксом `cost` — то есть ровно то, что и так выполняется. Я написал набор,
проверяющий соседнюю дверь.

### Починка, которая внесла новый канал

Дублируя CHECK периода занятости, я сравнил слитую пару — патч поверх сохранённой строки. Правильно
по существу: PATCH может нести только дату увольнения. И это дало оракул: `{terminatedAt: X}`
отвечает 422 выше некоторого X и 200 ниже, то есть двоичным поиском выдаёт `hiredAt` коллеги тому,
кто персональную половину читать не вправе. Тот же класс, что и деградация сортировки по дате найма,
только через запись.

Закрыто: для вызывающего вне персональной аудитории пара судится по телу запроса, хранимая строка не
читается вовсе. Цена честная и видна в тестах — такой вызывающий обязан прислать **обе** даты;
правка «вслепую» теперь требует назвать весь период.

### Комментарии, которые лгали

Девятнадцать заявок, и три из них требовали чинить код, а не текст:

- `facets()` обещал «`distinct` — работа базы», а Prisma без `nativeDistinct` дедуплицирует в памяти
  движка и push-down не делает при `orderBy`: на каждый debounce-нутый keystroke вычитывались все
  назначения ролей организации. Переписано на `some` → `EXISTS`;
- оргструктура строилась из кадровых записей, обещая «every node»: аккаунт без записи (принявший
  приглашение утром) был в таблице и отсутствовал на схеме тех же людей. Переписано на `users` —
  и isolation-тест сразу показал владельца организации, которого раньше не было;
- `accept-invitation` не писал строку в лог ровно для тех отказов, ради которых нужен алерт «один
  адрес, четыреста отказов».

Два места потребовали правды вместо обещаний. Комментарий ссылался на несуществующий тест
`schema-drift` — вместо смягчения формулировки написан настоящий тест, сверяющий `DIRECTORY_STATUSES`
с enum'ом Prisma. Утверждение «`team:read` нет у разработчика» оказалось неверным: право есть у всех,
кроме гостя, а настоящая причина фасетов разная для ролей (`role:read` кончается на `manager`) и для
команд (эндпоинта пока нет).

### Гейты, сработавшие до того, как их запустили

Три проверки уронили сборку сами, без агентов: исчерпывающая таблица deny-reason'ов не собралась,
пока новый код отказа не получил статус; контрактный тест сверил каталог ошибок со спекой и потребовал
опубликовать код там; `catalog-matches-model` потребовал описать причину в `permission-model.md`.
Это и есть польза дублирования с измерением — источник истины отказался расходиться молча.

## Что стоит унести

- **Ассерт над строкой SQL — не проверка.** Если оператор raw, его надо исполнить; записанный драйвер
  подтверждает только то, что строка составлена.
- **Уровни доступа — только если порядок реален.** Иначе флаги: пара булевых не умеет ошибиться в ту
  сторону, в которую ошиблась лестница.
- **Каждый CHECK, достижимый из публичного API, обязан иметь имя в каталоге отказов.** Иначе база
  отвечает вместо приложения, и отвечает кодом, которого нет.
- **Судья находит то, чего не находят специалисты.** Не потому что умнее — потому что его задача
  сформулирована как «сверь показания», а не «проверь свою тему».
- **Комментарий — тоже утверждение, и его надо проверять.** Отдельный проход «что здесь написано
  неправдой» дал три блокера из четырёх.

## Применённые технологии

- [[PostgreSQL]] — `ON CONFLICT` по индексу против ограничения; CHECK как источник отказа.
- [[Prisma]] — `distinct` как постобработка движка, а не SQL `DISTINCT`.
- [[Vitest]] — записанный драйвер и его граница применимости; положительный контроль как условие.
- [[Testcontainers]] — единственный способ проверить raw SQL.
