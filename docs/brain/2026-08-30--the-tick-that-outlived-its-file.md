# Галочка, пережившая свой файл

## Простым языком

1. В истории `story-011-01` нашлись три отмеченных галочкой задачи, называющие файлы, которых нет
   вовсе, — и проза той же истории двумя абзацами ниже честно писала, что две из трёх открыты.
   Галочка и текст противоречили друг другу внутри одного файла, и правдой был текст: его писал тот,
   кто перечитывал код, а галочку ставил тот, кто закрывал задачу.
2. Завёл узкий гейт на ровно этот класс: **отмеченный пункт, называющий путь репозитория, обязан
   называть существующий путь.** Неотмеченные пункты не читаются вовсе — `- [ ]` на ненаписанный
   файл это и есть назначение неотмеченного пункта.
3. Сначала померил наивную реализацию — «любой путь из любого места отмеченной строки». Она даёт
   595 находок на `epics/**`; гейт, который открывается красным на 595 строк, удаляют в первую
   неделю. Разбор только инлайн-кода и только форм, похожих на путь этого репозитория, даёт 116.
4. Прогнал гейт по всему `epics/**` и починил найденное в самих историях: где файл существует под
   другим именем — исправил путь, где не существует ничего — снял галочку и написал, что есть на
   самом деле, не удаляя обещания.
5. Добавил `epics/**` в `inputs` задачи `//#test:repo`. Без этого turbo отдавал бы кешированный
   PASS над файлами, которые задача ни разу не перечитала.

## Технически

1. `test/repo/epic-path-claims.util.ts` — ридер. Заявка = инлайн-код внутри пункта `- [x]`
   (включая строки-продолжения: длинный пункт переносит путь на вторую строку, и в `story-011-01`
   именно там он и стоял). Фенсы вырезаются до разбора. Токен считается путём, если содержит `/`,
   не содержит `[\s'"()=@:$<>]`, не начинается с `/` или `~`, и либо оканчивается на расширение из
   закрытого списка, либо открывается корнем репозитория (`packages|docs|test|scripts|epics|rules|
   .github|.claude`). Формы-плейсхолдеры: `{en,ru}` **раскрывается** (обе ветки — заявки, и именно
   в этой форме написана i18n-строка, с которой всё началось), `*`, `<name>`, `...`/`…` —
   **пропускаются** с обоснованием в докстринге.
2. Разрешение — `resolves()`: путь есть как есть либо какой-то путь дерева оканчивается на `/`+токен
   (по границе сегмента). Пакетно-относительная форма — то, как корпус пишет пути в 60% случаев;
   ридер, требующий якорной формы, забраковал бы большинство верных пунктов.
3. Дерево строится обходом `.github .claude docs epics packages rules scripts test` с отсечением
   `node_modules|dist|coverage|worktrees|...`. `worktrees` — существенное: `.claude/worktrees/<id>`
   это полный второй чекаут этого же репозитория, создаваемый параллельными агентами; обход по нему
   разрешал бы переименованный путь по копии дерева, и гейт зеленел бы или краснел в зависимости от
   того, какие агенты сейчас работают.
4. `listRepoFiles` в `test/repo/repo-fixture.util.ts` получил необязательный второй параметр `skip`
   — иначе обход `packages` уходит в `node_modules`.
5. `FOREIGN_PATHS` — именованные исключения с причиной (`dist/main.js`,
   `nodemailer/lib/nodemailer.js`), тот же приём, что `FOREIGN_*` в `runbook-claims.util.ts`.
   `PENDING` пуст и таков по замыслу: запись в нём — признание, что **галочка неверна**, а лечится
   это снятием галочки, а не записью. Обе проверки устаревания реестра на месте — запись о закрытом
   пробеле валит тест так же, как незаявленный пробел.
6. `turbo.json` — `epics/**` в `inputs` задачи `//#test:repo`. Проверено: до правки
   `test/repo/workspace-layout.test.ts` («covers every repository file the root suite reads») падал
   со списком из 185 непокрытых файлов `epics/**`.
7. Красное доказано двумя мутациями: галочка на пункте с несуществующим путём и опечатка в имени
   существующего файла внутри отмеченного пункта — обе валят гейт, обе возвращены.
