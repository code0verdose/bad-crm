# Glossary — Bad CRM

Связанные документы: [prd.md](./prd.md) · [roadmap.md](./roadmap.md) · [борд эпиков](../../epics/README.md)

## Как пользоваться

Это **ubiquitous language** проекта: единый словарь домена для продукта, кода и общения с заказчиком.
Правила обязательны:

1. **Имена совпадают везде.** Термин из колонки *Term (EN)* — это и имя Prisma-модели (`PascalCase`, ед.
   число), и корень имени FSD-unit (`kebab-case`, **ед. число**), и имя в API-контракте. Расхождение
   считается ошибкой и правится в коде, а не в глоссарии. Канон — единственное число: `units/task`,
   `units/file`, `units/dashboard`; формы с окончанием `-s` (`units/tasks`, `units/files`,
   `units/dashboards`) запрещены.
   Норматив — [`rules/naming-and-structure.mdc`](../../rules/naming-and-structure.mdc), п. 11.
   *Приведено к единственному числу 2026-07-26.*
2. **Русский — для общения, английский — для кода.** В интерфейсе и документах используем русский термин из
   колонки *Термин (RU)*; в идентификаторах, схемах и логах — только английский.
3. **Новый термин заводится здесь первым.** Сущность не появляется в схеме БД раньше, чем строка в этой
   таблице; в противном случае db-reviewer возвращает изменение на гейте коммита.
4. **Синонимы запрещены.** «Сотрудник» и «юзер» — разные сущности (см. `EmployeeProfile` и `User`),
   «доска» и «канбан» — одно и то же, и в коде живёт только `Board`. То же для имён юнитов —
   зафиксированы канонические варианты: `units/iam` (не `permissions`/`roles`/`access`),
   `units/kb` (не `knowledge-base`), `units/time` (не `time-tracking`), `units/dashboard`
   (не `dashboards`). **`units/iam` и `units/organization` разведены намеренно:** `iam` — про
   идентичность и доступ (разрешения, роли, назначения, персональные исключения, ACL, приглашения,
   сброс второго фактора администратором), `organization` — про сам арендатор и его настройки
   (переключатель организаций, `Organization.settings`, передача владения, bootstrap инсталляции).
   Права в `organization` не живут, настройки арендатора в `iam` не живут.
   *Разведение зафиксировано 2026-07-26.*
5. Колонка *Unit / Entity* указывает основное место жизни термина: FSD-unit на клиенте и/или Prisma-модель
   на сервере. Прочерк означает, что термин — понятие, а не персистентная сущность.
6. **Источник правды по именам Prisma-моделей — [`../architecture/data-model.md`](../architecture/data-model.md).**
   При расхождении правится глоссарий, а не модель данных.

## Мультиарендность и организация

| Термин (RU) | Term (EN) | Определение | Unit / Entity |
|---|---|---|---|
| Организация | Organization | Верхнеуровневый контейнер и **единица изоляции данных**: компания или команда, развернувшая или использующая инсталляцию. Все данные принадлежат ровно одной организации | `units/organization` / Prisma: `Organization` |
| Арендатор | Tenant | Синоним организации в контексте изоляции. Термин применяется только при обсуждении RLS, контекста запроса и безопасности; в схеме БД отдельной сущности нет | — (концепт; носитель — `Organization`) |
| Идентификатор арендатора | Tenant ID | Поле `organizationId`, присутствующее в каждой мультиарендной таблице. Основание для политик RLS и для фильтрации в поиске | Prisma: поле `organizationId` |
| Политика RLS | Row Level Security policy | Правило PostgreSQL, ограничивающее видимость строк текущим арендатором. Обязательна для каждой мультиарендной таблицы; её отсутствие ломает CI | — (`pg_policy`) |
| Контекст запроса | Request context | Набор данных о текущем запросе — организация, актор, права, локаль, — прокидываемый через слои сервера и задающий переменную сессии БД | — (серверный слой) |
| Настройки организации | Organization settings | Конфигурация уровня арендатора: язык по умолчанию, обязательность 2FA, рабочие часы, валюта, политика хранения файлов | Prisma: `Organization.settings` (JSONB; отдельной таблицы настроек нет) |

## Аутентификация и учётные записи

| Термин (RU) | Term (EN) | Определение | Unit / Entity |
|---|---|---|---|
| Аутентификация (клиентская) | Authentication | Механика доступа на стороне браузера: токен в памяти, обновление по 401 с дедупом, события входа и выхода. Токен **не** попадает в Web Storage — это инвариант №3, и его стережёт отдельное правило линтера | `units/auth` |
| Сессия (клиентская) | Session | То, что вкладка знает о текущем входе: есть ли живой доступ, идёт ли обновление, разлогинен ли пользователь. **Не** серверная `Session` (та — строка в БД с refresh-семейством). Сегодня это ещё и эталонный юнит клиента: на нём проверяются правила слоёв, потому что он не зависит ни от одного домена. **Временное разделение:** механика живёт в `units/auth`, состояние — здесь; в EPIC-006, когда появится настоящий вход, они объединяются в `units/auth`, а этот юнит удаляется вместе со своей ролью эталона | `units/session` / серверный аналог — Prisma: `Session` |
| Пользовательская учётная запись | User | Аутентификационная сущность внутри организации: email (уникален в рамках организации), хеш пароля (Argon2id), TOTP, статус (`ACTIVE`/`SUSPENDED`/`INVITED`), локаль, `lastSeenAt`. Не содержит кадрового контекста. Человек, работающий в двух инсталляциях или организациях, имеет две учётные записи — общего «глобального» пользователя в модели нет | `units/auth` / Prisma: `User` |
| Кадровый профиль сотрудника | EmployeeProfile | Рабочая запись о человеке: должность, отдел, руководитель, недельная ёмкость, тип занятости, даты найма и увольнения. Связь с учётной записью — 1:1; не у каждой учётной записи есть профиль (подрядчик, контакт заказчика, сервисный бот) | `units/employee` / Prisma: `EmployeeProfile` |
| Статус членства | Membership status | Состояние участия учётной записи в организации: активен, приглашён, деактивирован. Отдельной таблицы `Membership` нет — состояние выражается `User.status` и `EmployeeProfile.terminatedAt` | Prisma: `User.status` |
| Приглашение | Invitation | Одноразовое предложение присоединиться к организации с предустановленной ролью; имеет срок жизни и статус | `units/iam` / Prisma: `Invitation` |
| Сессия | Session | Активный вход учётной записи с устройства: время начала, IP, user-agent, признак доверенности | Prisma: `Session` |
| Токен обновления | Refresh token | Долгоживущий токен для продления сессии без повторного ввода пароля; ротируется при каждом использовании | Prisma: `Session.refreshTokenHash` (отдельной таблицы нет — ротация внутри `Session`) |
| Двухфакторная аутентификация | Two-factor authentication (TOTP) | Второй фактор входа по одноразовому коду на основе времени. Может быть сделан обязательным на уровне организации | `units/auth` / Prisma: `User.totpSecretEnc` / `User.totpEnabledAt` |
| Код восстановления доступа | Recovery code | Одноразовый код для входа при утере второго фактора. Не имеет отношения к recovery kit хранилища секретов | Prisma: `User` (argon2id-хеши кодов; отдельная таблица заводится в EPIC-013) |
| Офбординг | Offboarding | Единая операция прекращения доступа сотрудника: деактивация членства, отзыв сессий, отзыв ключей общих хранилищ, снятие с задач. Данные сотрудника сохраняются для ссылочной целостности | `units/employee` |

## Права и доступы

| Термин (RU) | Term (EN) | Определение | Unit / Entity |
|---|---|---|---|
| Разрешение | Permission | Атомарное право на действие над типом ресурса, например `task:update` или `vault:share`. Каталог разрешений закрыт: право вне каталога не существует | `units/iam` / Prisma: `Permission` |
| Роль | Role | Именованный набор разрешений, назначаемый сотруднику | `units/iam` / Prisma: `Role` |
| Системная роль | System role | Предустановленная неудаляемая роль: владелец, администратор, руководитель проекта, тимлид, разработчик, наблюдатель | Prisma: `Role.isSystem` |
| Кастомная роль | Custom role | Роль, созданная организацией из каталога разрешений | Prisma: `Role.isSystem = false` |
| Назначение роли | Role assignment | Связь сотрудника с ролью, опционально ограниченная областью действия (организация или конкретный проект) | Prisma: `UserRole` |
| Персональное исключение прав | Permission override | Точечное разрешение или запрет для конкретного сотрудника поверх его ролей. Реализует требование «кастомно по каждому юзеру» | Prisma: `UserPermissionOverride` |
| Список доступа к ресурсу | Resource ACL | Права на конкретный экземпляр ресурса (задачу, доску, документ, папку, хранилище) для сотрудника или роли | Prisma: `ResourceAcl` |
| Субъект | Principal | Сторона, которой выдаётся доступ: сотрудник, роль или системный актор | — (концепт) |
| Область действия | Scope | Граница применения роли или разрешения: организация, проект, ресурс | Prisma: `UserRole` + `ResourceAcl` (scope выражается уровнем гранта) |
| Разрешение доступа | Access resolution | Детерминированный алгоритм вычисления итогового доступа — **конъюнкция двух независимых проверок**: `allow = hasPermission(роли ∪ ALLOW-override) AND aclAllows(ресурс)`, поверх которых явный `DENY` в `UserPermissionOverride` и уровень `NONE` в `ResourceAcl` перебивают любое разрешение; при нескольких грантах ACL выигрывает максимальный уровень. Существует в коде ровно в одном месте (`domain/**/access/*.policy.ts`) | `units/iam` |
| Журнал действий | Audit log | Append-only журнал значимых действий: актор, объект, состояние до и после, IP, время. Не редактируется и не удаляется из интерфейса | `units/audit` / Prisma: `AuditLog` |

## Проект

| Термин (RU) | Term (EN) | Определение | Unit / Entity |
|---|---|---|---|
| Проект | Project | Центральная модель продукта: единица работы, к которой привязаны задачи, документы, заметки, файлы, хранилища секретов, время, каналы чата, спринты и финансы | `units/project` / Prisma: `Project` |
| Участник проекта | Project member | Связь сотрудника с проектом и его роль в проекте (руководитель, тимлид, исполнитель, наблюдатель). Основание для выдачи доступов, включая ключи общих хранилищ | Prisma: `ProjectMember` |
| Статус проекта | Project status | Состояние жизненного цикла: черновик, активный, приостановлен, завершён, архивный | Prisma: `Project.status` |
| Архивация | Archiving | Перевод сущности в режим только для чтения с сохранением всех связей. Не является удалением | — (поле `archivedAt`) |
| Код проекта | Project key | Короткий уникальный префикс проекта, используемый в человекочитаемых идентификаторах задач (например `BAD-142`) | Prisma: `Project.key` |

## Задачи и доски

| Термин (RU) | Term (EN) | Определение | Unit / Entity |
|---|---|---|---|
| Доска | Board | Канбан-представление набора задач с колонками. Принадлежит проекту либо команде | `units/board` / Prisma: `Board` |
| Колонка | Board column | Вертикальная стадия рабочего процесса на доске; задаёт статус попадающих в неё задач | Prisma: `BoardColumn` |
| Дорожка | Swimlane | Горизонтальная группировка задач на доске (по исполнителю, приоритету, эпику) | Prisma: `Board.settings` (отдельной таблицы нет) |
| Лимит незавершённой работы | WIP limit | Максимальное число задач в колонке; превышение подсвечивается как проблема процесса | Prisma: `BoardColumn.wipLimit` |
| Задача | Task | Единица работы: тип, статус, приоритет, исполнитель, срок, оценка, описание. Основной объект ежедневной работы | `units/task` / Prisma: `Task` |
| Подзадача | Subtask | Задача, вложенная в родительскую; полноценная задача, а не пункт чек-листа | Prisma: `Task.parentTaskId` |
| Связь задач | Task link | Типизированное отношение между двумя задачами: блокирует, заблокирована, дублирует, относится к, предшествует | Prisma: `TaskLink` |
| Метка | Label | Цветной ярлык для сквозной классификации задач внутри организации | Prisma: `Label` |
| Исполнитель | Task assignee | Сотрудник, отвечающий за выполнение задачи. Исполнителей может быть несколько, но ровно один помечен основным (`isPrimary`) — он же показывается на карточке доски и используется в отчётах | Prisma: `TaskAssignee` |
| Наблюдатель | Watcher | Сотрудник, подписанный на изменения задачи без ответственности за неё | Prisma: `Watcher` (полиморфная: задача, документ, заметка) |
| Оценка | Estimate | Плановая трудоёмкость задачи в часах; сопоставляется с фактом из записей времени | Prisma: `Task.estimateMinutes` (целые минуты, часы дробью не хранятся) |
| Сохранённое представление | Saved view | Именованный набор фильтров, сортировки и группировки списка задач; воспроизводится через параметры URL | Prisma: `SavedView` (в data-model не описана — пробел, закрывается в EPIC-019) |

| Вложение | Attachment | Связь файла с родительской сущностью (задачей, комментарием, документом, сообщением). Удаление родителя каскадно удаляет вложение и объект в хранилище | `units/collaboration` / Prisma: `Attachment` |
| Событие активности | ActivityEvent | Запись об изменении сущности для ленты и истории: кто, что и когда изменил. Источник данных для drill-down по сотруднику. **Не путать с `Activity`** — справочником видов трудозатрат в трекинге времени | Prisma: `ActivityEvent` |
| Реакция | Reaction | Эмодзи-отклик на сообщение или комментарий | Prisma: `MessageReaction` |
