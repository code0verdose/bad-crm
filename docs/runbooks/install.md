> **Статус: поставки ещё нет, но часть команд уже работает.** `.env.example` и dev-стек
> (`docker-compose.yml` с Postgres, Redis, MinIO, Meilisearch, Mailpit) существуют с EPIC-001.

## 1. Требования

### Железо и ОС

| Профиль | Сервисы | CPU / RAM | На кого рассчитан |
|---|---|---|---|
| `minimal` | app + PostgreSQL + Redis + MinIO | 2 vCPU / 2 GB | до ~20 активных пользователей, без поиска и AI |
| `default` (он же `full`) | + Meilisearch | 2 vCPU / 4 GB | до ~100 пользователей |
| `scaled` | + отдельные worker-контейнеры, внешний S3 / managed PostgreSQL | 4+ vCPU / 8+ GB | 100+ пользователей, несколько организаций |

- **Диск:** 10 GB под систему и образы плюс объём ваших данных. Файлы (MinIO) растут быстрее всего;
  закладывайте место и под бэкапы, если храните их локально (не рекомендуется — см. п. 6).
- **ОС:** Linux x86-64 или arm64. Docker 24+ с Compose v2.
- **Сеть:** доменное имя и TLS-сертификат. Приложение без HTTPS в продакшене не разворачивается:
  cookie с `Secure`, HSTS и WebSocket рассчитаны на TLS.

### Что понадобится заранее

- Reverse-proxy с TLS (Caddy, nginx или Traefik) — в поставку **не входит**, вы ставите его сами.
- SMTP-сервер, если нужны приглашения, восстановление пароля и уведомления по почте. Без него
  приложение работает, но письма не уходят.
- Место для бэкапов **вне этого хоста**.

## 2. Установка

```bash
git clone https://github.com/code0verdose/bad-crm.git
cd bad-crm
cp .env.example .env
```

### 2.1 Обязательные переменные окружения

Откройте `.env` и заполните всё, где стоит плейсхолдер `CHANGE_ME_…`. Приложение **не стартует**,
если хотя бы одна обязательная переменная отсутствует или невалидна: конфигурация разбирается схемой
один раз при старте, и ошибка конфигурации — это отказ старта, а не 500 через час работы.

| Переменная | Что это | Как получить |
|---|---|---|
| `APP_URL` | Публичный URL инсталляции | `https://crm.example.com` — именно тот адрес, по которому ходят пользователи. Используется для CORS, cookie и ссылок в письмах |
| `DATABASE_URL` | Подключение к PostgreSQL под ролью **приложения** | Строится из логина/пароля роли `app_user`, созданной при инициализации БД. Эта роль **не имеет `BYPASSRLS`** и не владеет таблицами |
| `REDIS_URL` | Подключение к Redis | `redis://redis:6379` внутри compose-сети |
| `JWT_SECRET` | Секрет подписи access-токенов, ≥ 32 символа | `openssl rand -base64 48` |
| `APP_ENCRYPTION_KEY` | 32 байта в base64 — шифрует секреты интеграций at rest | `openssl rand -base64 32` |
| `S3_ENDPOINT` | Адрес объектного хранилища | `http://minio:9000` внутри compose-сети или адрес внешнего S3 |
| `S3_BUCKET` | Имя бакета | Создаётся при первом старте или вручную |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Креды к хранилищу | Для MinIO — те, что вы зададите в его переменных; **не оставляйте дефолтные** |

### 2.2 Генерация ключей

```bash
# APP_ENCRYPTION_KEY — ровно 32 байта, base64
openssl rand -base64 32

# JWT_SECRET — длинная случайная строка
openssl rand -base64 48

# пароль для роли PostgreSQL, master key для Meilisearch, креды MinIO
openssl rand -base64 24
```

> **⚠️ `APP_ENCRYPTION_KEY` — не «просто ещё один секрет».**
>
> Им зашифрованы в базе API-ключи AI-провайдеров, SMTP-пароли, GitHub-токены, webhook-секреты и
> TOTP-секреты пользователей. **Потеря ключа делает всё это невосстановимым** — восстановление из
> бэкапа не поможет, потому что в бэкапе лежит шифротекст. Утечка ключа означает компрометацию всех
> перечисленных секретов сразу.
>
> Сохраните его отдельно от сервера (менеджер паролей, offline-носитель) **до** первого запуска.
> Сгенерировать «такой же» задним числом невозможно.
>
> Важно: `APP_ENCRYPTION_KEY` **не имеет отношения к E2EE-хранилищу**. Vault шифруется ключами,
> которые выводятся из мастер-пароля пользователя в браузере; на сервере их нет и они не зависят от
> этой переменной.

### 2.3 Опциональные переменные

Отсутствие любой из них деградирует функцию, но не ломает старт. Здоровье выключенных сервисов не
влияет на `/ready` — иначе инстанс в профиле `minimal` никогда не стал бы готовым.

| Переменная | Что будет, если не задана |
|---|---|
| `SMTP_URL` | Письма пишутся в лог (dev) / почтовые операции падают с внятной ошибкой (prod) |
| `MEILI_HOST` + `MEILI_MASTER_KEY` | Поиск деградирует до полнотекста PostgreSQL; в интерфейсе баннер об ограничении. Задавать обе или ни одной |
| `AI_ENABLED` | По умолчанию `false`: AI-функции скрыты и возвращают `feature_disabled` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Трейсы не экспортируются; логи и метрики работают |
| `LOG_LEVEL` | По умолчанию `info` |
| `RUN_WORKERS_IN_PROCESS` | По умолчанию `false` (воркер — отдельный контейнер). `true` — осознанное исключение для профиля `minimal` на одной машине |
| `CORS_EXTRA_ORIGINS` | Разрешён только `APP_URL` |

**Ключей LLM-провайдеров в `.env` нет и быть не должно.** Их вводит администратор организации в
интерфейсе, и они хранятся зашифрованными в базе. `AI_ENABLED` — только общеинсталляционный
выключатель.

### 2.4 Запуск

**Установка (EPIC-017), дистрибутивный файл:**

```bash
# полный профиль (с поиском)
docker compose -f docker-compose.prod.yml --profile default up -d

# минимальный профиль (без Meilisearch)
docker compose -f docker-compose.prod.yml --profile minimal up -d
```

**Разработка, репозиторий:** `docker-compose.yml` поднимает только backing-сервисы; приложение
бежит на хосте через `pnpm dev`.

```bash
pnpm docker:up            # полный набор: + Meilisearch и Mailpit
pnpm docker:up:minimal    # минимальный набор
```

> **`docker compose up -d` без флагов поднимает `minimal`, а не полный набор.** Compose умеет
> добавлять сервис в профиль, но не умеет исключать: Meilisearch и Mailpit объявлены с
> `profiles: [default, full]` и поэтому по умолчанию не стартуют, а остальные сервисы стартуют в
> любом профиле. Полный набор — это `pnpm docker:up`, `docker compose --profile default up -d` или
> `COMPOSE_PROFILES=default` в `.env`. Обёртка `pnpm docker:up` нужна ещё и потому, что `--wait`
> считает падением любой вышедший контейнер, включая одноразовый инициализатор бакета MinIO,
> который обязан выйти с кодом 0.

Порядок старта: контейнеры БД → одноразовый job миграций → `api` и `worker`. Миграции выполняются
под отдельной ролью-владельцем схемы, приложение — под ролью без `BYPASSRLS`. Это не деталь
реализации, а часть модели изоляции: см. [`../security/rls-design.md`](../security/rls-design.md).

Следите за логами первого старта:

```bash
docker compose logs -f
```

Типичные причины отказа старта: невалидный `APP_ENCRYPTION_KEY` (не 32 байта после base64-декода),
`MEILI_HOST` без `MEILI_MASTER_KEY`, недоступный PostgreSQL, `APP_URL` без схемы.

## 3. Reverse-proxy и TLS

Приложение не терминирует TLS само. Минимальные требования к прокси:

- HTTPS с валидным сертификатом; HTTP редиректится на HTTPS.
- Проксируются `/api`, `/socket.io` и статика SPA.
- **Sticky sessions на `/socket.io`** — пока разрешён HTTP long-polling fallback Socket.IO,
  рукопожатие и последующие polling-запросы должны попадать в один инстанс. Настраивается по
  cookie или ip-hash. Если инстанс один, это неактуально.
- Проброс `X-Forwarded-For` и `X-Forwarded-Proto`, иначе rate-limit будет считать всех одним IP, а
  cookie не получат `Secure`.
- WebSocket-upgrade разрешён.
- Таймаут на upgrade-соединения — не меньше нескольких минут, иначе чат будет постоянно
  переподключаться.

Пример на Caddy:

```caddyfile
crm.example.com {
    encode gzip
    reverse_proxy app:3000
}
```

Caddy сам получает сертификат Let's Encrypt и проксирует WebSocket без дополнительной настройки.

## 4. Первый вход и создание владельца

1. Откройте `APP_URL` в браузере.
2. Экран регистрации предлагает создать **первую организацию**. Пользователь, создавший её,
   становится её **владельцем** (owner) — роль с полным набором прав внутри организации.
3. Заполните имя организации, email и пароль. Пароль хешируется argon2id; минимальные требования
   проверяются формой.
4. После входа вы попадаете в пустую оболочку приложения. Выберите язык интерфейса (EN или RU) —
   оба равноправны.

**Сразу после первого входа:**

- Включите **двухфакторную аутентификацию** для аккаунта владельца, как только TOTP доступен
  (EPIC-013, майлстоун M2). Владелец — самая ценная учётная запись в системе.
- Проверьте, что регистрация новых организаций закрыта или ограничена, если инсталляция не
  предназначена для публичного использования.
- Пригласите остальных участников через интерфейс, а не создавайте им учётные записи вручную в базе.

> **Важно про роль владельца организации и владельца инсталляции.** Это разные вещи. Владелец
> организации имеет полные права **внутри своей организации** и не видит данные других организаций
> (изоляция на уровне БД через RLS). Владелец **инсталляции** — тот, у кого есть доступ к серверу,
> диску, базе и бэкапам — технически имеет доступ к данным всех организаций на этом хосте, кроме
> шифротекста vault. Это модель поставки, а не уязвимость; она документирована как остаточный риск
> RR-02 в [`../security/threat-model.md`](../security/threat-model.md). Если инсталляция должна
> обслуживать юридически независимые компании, единственный честный ответ — отдельные инстансы.

## 5. Чек-лист безопасности после установки

Выполняется **до того**, как в системе появятся реальные данные. Проверки, отмеченные «извне»,
делаются с другой машины, а не с самого хоста — изнутри всё всегда выглядит правильно.

### 5.1 Сеть: наружу торчит только прокси

- [ ] PostgreSQL (5432), Redis (6379), MinIO (9000 и консоль 9001), Meilisearch (7700) **не
      опубликованы наружу**. В `docker-compose.yml` у них не должно быть секции `ports:` с
      привязкой к `0.0.0.0` — только внутренняя сеть Docker или явно `127.0.0.1:PORT`.
- [ ] Проверено **извне**:
      ```bash
      nmap -Pn -p 22,80,443,5432,6379,7700,9000,9001 crm.example.com
      ```
      Открытыми должны быть только 80, 443 и, при необходимости, ваш SSH-порт.
- [ ] Firewall хоста (ufw/nftables/облачная группа безопасности) разрешает входящие только на
      нужные порты. Помните, что Docker умеет обходить `ufw`, публикуя порты напрямую в
      `iptables` — поэтому проверка `nmap` извне обязательна, а не «я же настроил ufw».
- [ ] Консоль MinIO (9001) не опубликована. Если она нужна — только через SSH-туннель.

### 5.2 TLS

- [ ] HTTPS работает, сертификат валиден, автообновление настроено.
- [ ] HTTP редиректится на HTTPS.
- [ ] `APP_URL` содержит `https://` — от этого зависят `Secure` на cookie и HSTS.
- [ ] Проверено: `curl -I https://crm.example.com` возвращает `Strict-Transport-Security`.

### 5.3 Дефолты изменены

- [ ] Пароль роли PostgreSQL — сгенерированный, не из примера.
- [ ] Креды MinIO (`MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD`) изменены. Значения вида
      `minioadmin/minioadmin` — это открытая дверь.
- [ ] `MEILI_MASTER_KEY` задан (Meilisearch без master key в проде работает как открытая база).
- [ ] `JWT_SECRET` и `APP_ENCRYPTION_KEY` сгенерированы CSPRNG и уникальны для этой инсталляции.
- [ ] Ни одного `CHANGE_ME_` не осталось: `grep -n 'CHANGE_ME' .env` пуст.
- [ ] Права на `.env` — `600`, владелец — пользователь, от которого запускается Docker.
- [ ] `.env` не попал в git: `git check-ignore -v .env` подтверждает игнорирование.

### 5.4 База данных

- [ ] Роль приложения **не имеет `BYPASSRLS`**:
      ```sql
      SELECT rolname, rolbypassrls, rolsuper FROM pg_roles WHERE rolname LIKE 'app%';
      ```
      У роли приложения оба флага — `false`.
- [ ] Роль приложения **не владеет таблицами** (владелец — отдельная миграционная роль).
- [ ] На всех мультиарендных таблицах включён RLS **и** `FORCE`:
      ```sql
      SELECT relname, relrowsecurity, relforcerowsecurity
      FROM pg_class WHERE relkind = 'r' AND relnamespace = 'public'::regnamespace
        AND (relrowsecurity IS FALSE OR relforcerowsecurity IS FALSE);
      ```
      Выдача должна быть пустой, кроме явно задокументированных исключений
      ([`../security/rls-design.md`](../security/rls-design.md)).

### 5.5 Бэкапы

- [ ] Бэкап настроен **до** появления боевых данных.
- [ ] Бэкапится `pgdata` и `minio-data`; `meili-data` не бэкапится (производный индекс).
- [ ] Дамп снимается **под ролью `backup_role`** — она создаётся bootstrap-скриптом ролей с
      `BYPASSRLS` и без прав на запись. Под владельцем таблиц `pg_dump` при
      `FORCE ROW LEVEL SECURITY` либо падает, либо выгружает частичные данные. Подробно и с
      командами — [`backup-restore.md`](backup-restore.md).
      ```sql
      SELECT rolname, rolbypassrls FROM pg_roles WHERE rolname = 'backup_role';
      -- одна строка, rolbypassrls = true
      ```
- [ ] Каждая таблица, **каждая партиция** и каждая последовательность имеют
      `GRANT SELECT … TO backup_role`. `BYPASSRLS` снимает политики, но не гранты, а `pg_dump`
      берёт `ACCESS SHARE` на всё сразу, до чтения первой строки: один забытый `GRANT` роняет
      весь бэкап. Партиции — самый частый пропуск: грант родителя на лист не распространяется.
      ```sql
      SELECT c.relname, c.relkind, c.relispartition
      FROM   pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace
      WHERE  n.nspname = 'public'
        AND  ((c.relkind IN ('r','p') AND NOT has_table_privilege('backup_role', c.oid, 'SELECT'))
           OR (c.relkind =  'S'       AND NOT has_sequence_privilege('backup_role', c.oid, 'SELECT')));
      -- выдача должна быть пустой. Если запрос падает с `role "backup_role" does not exist` —
      -- bootstrap ролей на этой инсталляции не выполнялся, и бэкап снимать нечем.
      ```
      Раздаёт их `pnpm db:grants` (`packages/server/prisma/sql/01-grants.sql`) — он обходит каталог,
      поэтому покрывает и `_prisma_migrations`, и партиции, созданные джобом обслуживания. Запускать
      после каждой миграции и после каждого восстановления.
- [ ] Бэкапы уезжают **с этого хоста** и зашифрованы.
- [ ] `APP_ENCRYPTION_KEY` хранится **не там же**, где единственная копия бэкапов.
- [ ] Тестовое восстановление выполнено хотя бы один раз. Невосстановленный бэкап — это гипотеза.

### 5.6 Учётные записи и доступ

- [ ] У владельца организации включена 2FA (по мере доступности TOTP).
- [ ] SSH на хост — по ключам, без пароля; root-логин запрещён.
- [ ] Регистрация новых организаций ограничена, если инсталляция не публичная.
- [ ] Понятно, кто из людей имеет доступ к хосту, и этот список минимален: доступ к хосту = доступ ко
      всем данным всех организаций, кроме vault.

### 5.7 Логи и наблюдаемость

- [ ] `LOG_LEVEL=info` в продакшене. `debug` логирует тела запросов и не предназначен для прода.
- [ ] Хранилище логов считается чувствительным: там `userId`, `organizationId`, маршруты и коды
      ошибок. Доступ к нему ограничен так же, как к базе.
- [ ] Ротация логов настроена, диск не переполнится.

### 5.8 План на плохой день

- [ ] [`incident.md`](incident.md) прочитан **до** инцидента, а не во время.
- [ ] Известно, где взять `APP_ENCRYPTION_KEY`, если хост потерян.
- [ ] Известно, как быстро остановить приложение, сохранив данные.

## 6. Проверка работоспособности

```bash
# контейнеры подняты и здоровы
docker compose ps

# приложение отвечает
curl -fsS https://crm.example.com/healthz    # процесс жив
curl -fsS https://crm.example.com/readyz     # готов принимать трафик

# миграции применены
docker compose logs migrate | tail -n 30
```

Функциональная проверка, вручную:

1. Открыть `APP_URL` — SPA загружается, переключение EN/RU работает.
2. Войти под владельцем — вход проходит, сессия сохраняется после перезагрузки страницы.
3. Выйти и войти снова — refresh-ротация работает.
4. Если задан `SMTP_URL` — отправить приглашение и убедиться, что письмо дошло.
5. Если поднят Meilisearch — выполнить поиск; если нет, убедиться, что показан баннер об
   ограниченном поиске, а поиск всё равно работает через полнотекст PostgreSQL.
6. Загрузить файл — проверяется весь путь presigned URL до MinIO.

**Что означает «нездорово»:**

| Симптом | Наиболее вероятная причина |
|---|---|
| `/readyz` отдаёт 503 | Недоступен PostgreSQL или Redis; смотрите логи `api` |
| Приложение не стартует, в логе — сообщение о переменной | Ошибка конфигурации; исправьте `.env` и перезапустите |
| Вход проходит, но при перезагрузке разлогинивает | `APP_URL` не совпадает с реальным адресом, cookie не ставится |
| Чат постоянно переподключается | Прокси режет WebSocket или нет sticky sessions на `/socket.io` |
| Файлы не загружаются | `S3_ENDPOINT` недостижим из браузера (для presigned-загрузки адрес должен быть доступен клиенту, а не только контейнеру) |
| Поиск ничего не находит после включения Meilisearch | Нужна полная переиндексация из БД — индекс производный и изначально пуст |
