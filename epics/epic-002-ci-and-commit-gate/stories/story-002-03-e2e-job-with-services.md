# STORY-002-03 — E2E-job с поднятыми сервисами и артефактами

**Как** разработчик Bad CRM **я хочу** отдельную CI-джобу, которая поднимает полный стек и гоняет
Playwright **чтобы** сценарии «как у пользователя» проверялись на каждом PR, а не только руками
перед релизом.

## Acceptance (Given/When/Then)

- **Given** pull request **When** запускается job `e2e` **Then** поднимается docker-стек из `docker-compose.yml`, применяются миграции и seed, стартуют сервер и клиент, после чего выполняется `pnpm test:e2e`.
- **Given** сервисы, которым нужно время на инициализацию **When** job ждёт готовности **Then** ожидание идёт по healthcheck и `/ready`, а не по фиксированному `sleep`; таймаут ожидания — 5 минут с внятным сообщением.
- **Given** упавший e2e-сценарий **When** job завершается **Then** в артефакты выгружаются Playwright trace, скриншот и видео упавшего теста, а также логи контейнеров сервера и Postgres.
- **Given** зелёный прогон **When** job завершается **Then** тяжёлые артефакты (видео) не выгружаются — только HTML-отчёт, чтобы не раздувать хранилище.
- **Given** нестабильный тест **When** он падает и проходит при повторе **Then** он помечается как flaky в отчёте; повтор ограничен `retries: 1` в CI и `0` локально.
- **Given** сетевая песочница без исходящего интернета **When** прогоняется e2e **Then** сценарии проходят полностью: приложение не обращается к внешним CDN, шрифтам и телеметрии (проверка NFR-9).
- **Given** отменённый PR-прогон **When** пушится новый коммит **Then** предыдущий e2e-прогон отменяется группой concurrency и не занимает раннер.

## Задачи

- [ ] Написать e2e-заглушку `packages/e2e/tests/smoke/health.spec.ts` (открыть корень, дождаться загрузки оболочки) — она делает джобу проверяемой до появления реальных сценариев из [EPIC-010](../../epic-010-e2e-harness/epic.md).
- [ ] Создать job `e2e` в `.github/workflows/ci.yml` (или отдельный `e2e.yml`): `docker compose --profile default up -d --wait`, `pnpm db:migrate`, `pnpm db:seed`, старт приложения, `pnpm test:e2e`.
- [ ] Настроить кеш браузеров Playwright и установку только нужных браузеров (`--with-deps chromium` для PR, полный набор — по расписанию).
- [ ] Настроить условную выгрузку артефактов: `if: failure()` для trace/video/логов контейнеров, `always()` для HTML-отчёта.
- [ ] Добавить сбор логов контейнеров (`docker compose logs --no-color`) в артефакты при падении.
- [ ] Добавить проверку отсутствия исходящего интернета: прогон в job с блокировкой внешних доменов (или явный allow-list только на локальные адреса).
- [ ] Описать в `docs/runbooks/ci.md`, как локально воспроизвести e2e-джобу и как читать trace.
