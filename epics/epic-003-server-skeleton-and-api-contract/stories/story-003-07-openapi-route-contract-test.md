# STORY-003-07 — Двусторонний контрактный тест роутер ↔ спецификация

**Как** разработчик Bad CRM **я хочу** тест, который сверяет реальный роутер Express со
спецификацией в обе стороны **чтобы** ни один endpoint не существовал вне контракта и ни одна
описанная операция не оставалась нереализованной.

## Acceptance (Given/When/Then)

- **Given** зарегистрированный route `POST /api/v1/tasks`, отсутствующий в `openapi.yaml` **When** запускается контрактный тест **Then** он падает с сообщением «route не описан в спецификации: POST /api/v1/tasks».
- **Given** операция `GET /api/v1/tasks/{id}` в спецификации без соответствующего route **When** запускается контрактный тест **Then** он падает с сообщением «операция не реализована».
- **Given** route с параметром `/api/v1/tasks/:id` **When** тест нормализует пути **Then** он корректно приводит `:id` к `{id}` и сопоставляет с операцией спеки, независимо от имени параметра в коде.
- **Given** служебные пути `/health`, `/ready`, `/metrics`, `/socket.io` **When** запускается тест **Then** они не считаются нарушением — они перечислены в явном allow-list, который сам покрыт тестом на непустоту и отсутствие масок.
- **Given** метод, объявленный в спеке, но не зарегистрированный (описан `PATCH`, реализован только `PUT`) **When** запускается тест **Then** он падает: сверяется пара «путь × метод», а не только путь.
- **Given** каталог кодов ошибок `packages/shared/errors/codes.ts` **When** запускается тот же набор контрактных тестов **Then** проверяется совпадение множества кодов с `enum` в компоненте `Problem`.
- **Given** зелёный контрактный тест **When** он выполняется в CI **Then** он не требует поднятой БД и внешних сервисов — приложение собирается в тестовом режиме без подключений.
