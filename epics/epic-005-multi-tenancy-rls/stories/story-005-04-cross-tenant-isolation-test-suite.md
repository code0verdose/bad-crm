# STORY-005-04 — Набор тестов изоляции с положительным контролем

**Как** владелец инсталляции **я хочу** автоматический тест изоляции на каждую мультиарендную
таблицу **чтобы** отсутствие утечки было доказано машиной на каждом коммите, а не заявлено в
документации.

## Acceptance (Given/When/Then)

- **Given** список мультиарендных таблиц, выведенный **из схемы Prisma автоматически** **When** добавляется новая таблица с `organizationId` **Then** она сразу попадает в набор тестов без правки списка руками.
- **Given** строка организации B **When** в контексте организации A выполняется `SELECT` по её `id` **Then** результат пуст.
- **Given** строка организации B **When** в контексте A выполняются `UPDATE`, `DELETE` по её `id` **Then** затронуто 0 строк; данные организации B не изменились (проверяется повторным чтением под контекстом B).
- **Given** строки обеих организаций **When** в контексте A выполняются `SELECT *` (список) и `COUNT(*)` **Then** в выборку и в счётчик попадают только строки организации A.
- **Given** контекст организации A **When** выполняется `INSERT` со значением `organization_id` организации B **Then** запрос отклоняется политикой.
- **Given** контекст организации A и **своя** строка **When** выполняются чтение, обновление, удаление, список и счётчик **Then** все операции успешны и возвращают ожидаемые данные — **положительный контроль**: тест доказывает, что «пусто» вызвано изоляцией, а не сломанной фикстурой или пустой таблицей.
- **Given** таблица, у которой `organization_id` доступен только через родителя **When** для неё генерируется тест **Then** используется соответствующий шаблон из `rls-design.md`, а не пропуск таблицы.
- **Given** прогон набора в CI **When** он завершается **Then** отчёт перечисляет проверенные таблицы, а таблица без сгенерированного теста считается провалом.

## Задачи

- [ ] Написать генератор набора первым: `test/integration/rls/tenant-scoped-tables.ts` — читает Prisma DMMF, отбирает модели с полем `organizationId`, отдаёт список и метаданные (обязательные поля для фикстуры).
- [ ] Реализовать обвязку `test/integration/rls/harness.ts`: две организации (A и B) и по пользователю в каждой, `seedRowFor(org, table)` c генерацией минимально валидной строки, очистка между тестами.
- [ ] Реализовать параметризованный набор `test/integration/rls/rls-isolation.test.ts` с `describe.each(TENANT_SCOPED_TABLES)` и шестью группами проверок: read, update, delete, list, count, insert-with-foreign-org.
- [ ] Добавить в тот же набор блок **положительного контроля** — «своя строка видна и изменяема».
- [ ] Реализовать проверку «для каждой таблицы из списка существует тест», чтобы пропуск через `skip` не проходил незамеченным.
- [ ] Добавить отдельный тест для таблиц с наследуемым `organization_id` (через родителя) по шаблону из `rls-design.md`.
- [ ] Подключить набор к CI-джобе интеграционных тестов; падение любой проверки — блокирующее.
- [ ] Зафиксировать в `docs/security/rls-design.md` состав набора и порядок добавления новой таблицы.
