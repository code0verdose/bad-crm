# STORY-006-06 — Смена пароля и инвалидация остальных сессий

**Как** разработчик (пользователь продукта) **я хочу** сменить пароль и одновременно закрыть все
остальные сессии **чтобы** после подозрения на утечку одно действие возвращало контроль над
аккаунтом.

## Acceptance (Given/When/Then)

- **Given** аутентифицированный пользователь **When** он отправляет текущий и новый пароль **Then** пароль меняется, все сессии, кроме текущей, отзываются, их `sid` попадают в денилист, событие пишется в аудит.
- **Given** неверный текущий пароль **When** отправляется форма **Then** 422/401 с ошибкой по полю `currentPassword`; пароль не меняется, сессии не трогаются.
- **Given** новый пароль, совпадающий с текущим **When** отправляется форма **Then** запрос отклоняется с понятной ошибкой.
- **Given** новый пароль, не удовлетворяющий политике **When** отправляется форма **Then** 422 `validation_failed` по полю `newPassword`; та же Zod-схема применяется на клиенте до отправки.
- **Given** успешная смена **When** смотрю активные сессии **Then** остаётся ровно одна — текущая; на другом устройстве следующий запрос получает 401.
- **Given** успешная смена **When** проверяю почту **Then** отправлено уведомление о смене пароля (при отсутствии SMTP — запись в лог, операция не падает).
- **Given** множественные попытки смены с неверным текущим паролем **When** их больше лимита **Then** срабатывает rate limiting (см. [STORY-006-07](story-006-07-auth-rate-limiting-and-lockout.md)).

## Задачи

- [ ] Написать тесты первыми: `application/identity/use-cases/change-password.use-case.test.ts` (успех, неверный текущий, совпадение с текущим, слабый новый), `test/integration/auth/change-password.test.ts` (остальные сессии отозваны, текущая жива).
- [ ] Реализовать `application/identity/use-cases/change-password.use-case.ts` — проверка текущего пароля, перехеширование нового, отзыв прочих сессий в одной транзакции.
- [ ] Реализовать endpoint `POST /api/v1/auth/change-password` и описать его в `openapi.yaml`.
      *(2026-07-28: **описание сделано**, маркер `x-implemented-by: STORY-006-06`. Неверный
      `currentPassword` — `401 invalid_credentials`, тот же код, что у отказанного логина, а не
      422: поле корректно по форме, оно просто неверно, и попытка обязана попасть в тот же счётчик
      rate limiter'а. Привязку сообщения к полю делает клиент. Новый пароль, равный текущему, и
      пароль вне политики — 422 по `newPassword`. `Idempotency-Key` обязателен: операция шлёт письмо,
      а повтор потерянного ответа иначе падает с `invalid_credentials`, потому что «текущий» пароль
      уже сменён.)*
- [ ] Реализовать постановку уведомления по почте через порт `MailerPort`.
- [ ] Реализовать клиентскую форму на `/settings/security`: три поля, индикатор надёжности пароля, обработка ошибок по коду.
- [ ] Добавить запись в аудит-журнал и метрику числа смен пароля.
