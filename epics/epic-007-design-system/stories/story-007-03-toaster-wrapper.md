# STORY-007-03 — Обёртка тостера над @mantine/notifications

**Как** разработчик (пользователь продукта) **я хочу** получать ровно один понятный сигнал на одно
действие **чтобы** экран не заваливало пятью одинаковыми красными плашками при одной сетевой
ошибке.

## Acceptance (Given/When/Then)

- **Given** обёртка `notify` **When** вызываю `notify.success('…')` **Then** показывается зелёное уведомление; API обёртки — `success`, `error`, `loading`, `update`, `dismiss`, и вендорский `notifications.show` в компонентах не используется (проверяется линтером).
- **Given** пять одинаковых ошибок с одним `id` **When** они происходят подряд **Then** на экране остаётся одно уведомление, которое обновляется, а не пять одинаковых.
- **Given** долгая операция **When** она начинается **Then** показывается `loading`-уведомление с фиксированным `id`, которое по завершении **обновляется** в успех или ошибку тем же `id`, а не создаёт второе.
- **Given** мутация с локальным `onError` **When** она падает **Then** глобальный обработчик не добавляет второй тост — за один сбой ровно один вызов `notify.error`.
- **Given** отменённый запрос (`AbortError`) **When** он «падает» **Then** тост не показывается.
- **Given** уведомление об ошибке **When** оно показано **Then** текст выбран по коду ошибки из `errors.json`, а `detail` с сервера пользователю не выводится.
- **Given** скринридер **When** появляется уведомление **Then** оно объявляется: контейнер уведомлений имеет корректную роль (`status` для нейтральных, `alert` для ошибок), фокус не перехватывается.
- **Given** уведомление **When** оно показано **Then** оно закрывается по `Esc` и имеет доступную кнопку закрытия с текстовой меткой.
