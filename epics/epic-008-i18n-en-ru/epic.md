# EPIC-008 — Двуязычность EN/RU

## Зачем (ценность)

Два равноправных языка — часть обещания продукта, а не «перевод потом». Опыт показывает
единственный способ этого добиться: сделать хардкод-строку невозможной технически и завалить сборку
при ключе без пары. Эпик вводит инфраструктуру локализации, переключатель языка, перевод серверных
ошибок по кодам, линт против хардкода и локале-зависимое форматирование дат, чисел и валют — до
того, как в продукте появятся сотни экранов.

## Scope

### В скоупе

- `i18next` + `react-i18next`, раскладка namespace по юнитам, провайдер в `app/`, ленивая загрузка доменных namespace.
- Переключатель языка, сохранение выбора, определение начальной локали (профиль → `localStorage` → `Accept-Language`/`navigator.language` → `en`).
- Серверные ошибки как стабильные коды + маппинг код → сообщение на клиенте.
- `i18next-parser` и CI-проверка: непереведённые ключи и хардкод-строки в JSX валят сборку.
- Форматирование дат, чисел, валют и длительностей по локали через `Intl.*`.

### Вне скоупа

- Перевод пользовательского контента (задачи, документы) — контент языконезависим по определению.
- RTL-локали — не поддерживаются в 1.0; закладывается только использование логических CSS-свойств.
- Локализация писем доменных сценариев — в соответствующих эпиках (здесь только механизм и письма auth).
- Языковые настройки организации как значение по умолчанию для новых сотрудников — [EPIC-012](../epic-012-employee-management/epic.md) (здесь — только пользовательский выбор).

## Acceptance (эпик выполнен, когда)

- [ ] Весь интерфейс M1 доступен на английском и русском; ни одной хардкод-строки в JSX (проверяется линтером).
- [ ] Ключ, существующий только в одном языке, ломает сборку.
- [ ] Серверные ошибки приходят кодами; текст выбирается на клиенте из `errors.json`; неизвестный код даёт понятное общее сообщение, а не пустую строку.
- [ ] Множественное число корректно на русском (`one/few/many`) и английском (`one/other`); строки не собираются конкатенацией.
- [ ] Даты, числа, валюты и длительности форматируются через `Intl.*` с текущей локалью; ручных шаблонов вроде `dd.MM.yyyy` в компонентах нет.
- [ ] Переключение языка применяется без перезагрузки страницы, сохраняется в `localStorage` и (после [EPIC-012](../epic-012-employee-management/epic.md)) в профиле; `<html lang>` обновляется.
- [ ] Публичные экраны (`/login`, `/forgot-password`) имеют собственный переключатель языка — до входа профиля нет.
- [ ] Переводимы также `aria-label`, `title`, `placeholder`, `document.title` и сообщения live-region.

- Зависит от: [EPIC-004](../epic-004-client-shell-fsd/epic.md) (провайдеры и оболочка), [EPIC-003](../epic-003-server-skeleton-and-api-contract/epic.md) (каталог кодов ошибок).

- Риски: **R-17** (двуязычность деградирует до «английский + недоперевод») — митигируется линт-правилом на пары ключей, запретом хардкода и включением перевода в DoD; переполнение вёрстки русскими строками — митигируется псевдолокалью в мастерской компонентов ([STORY-008-06](stories/story-008-06-component-workshop-and-pseudo-locale.md), перенесена сюда из EPIC-007 2026-07-30: проверять переполнение вёрстки надо там, где появляются переводы).
