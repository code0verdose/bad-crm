**Закрыта 2026-08-04, с двумя записанными отступлениями.**

Сделано: `MetricsPort` + `prom-client.adapter.ts` (собственный реестр, дефолтные метрики Node) и
`noop-metrics.adapter.ts`; сборщик HTTP-метрик рядом с логгером в `infrastructure/metrics`;
`GET /metrics` за bearer-токеном; `METRICS_ENABLED` (по умолчанию **false**) и `METRICS_TOKEN`
с правилом «включено без токена — не стартуем»; счётчик `auth_rate_limited_total{endpoint}`;
каталог имён метрик в `rules/observability.mdc`; переменные задокументированы в `.env.example`
**и** в `docs/runbooks/upgrade.md`.

**Кардинальность проверена сквозным тестом,** а не только на адаптере: два запроса к двум разным
идентификаторам дают **один** ряд с меткой `route="/api/v1/tasks/:id"`, и в выводе нет самого
идентификатора. Отдельный контроль — что несопоставленный путь не становится своей меткой (иначе
сканер, перебирающий URL, кладёт инстанс).

**Доступ закрыт 404, а не 401:** вызывающий без токена не может даже подтвердить, что endpoint здесь
есть — то же рассуждение, что для чужой организации (инвариант 2). Сравнение токена —
`timingSafeEqual`, чтобы префикс не утекал по времени ответа.

**Отступление 1: `db_pool_active`/`db_pool_idle` не сделаны.** Они требуют preview-фичу `metrics`
в `prisma/schema.prisma` — это правка схемы со своим гейтом (`db-reviewer`), и она столкнётся с
миграцией на Prisma 7, которая тоже трогает генератор. Имена зарезервированы в каталоге метрик.

**Отступление 2: `auth_rate_limited_total` считается по статусу 429**, а не по типу исключения.
Причина архитектурная: тест слоёв запрещает `presentation` импортировать что-либо из
`infrastructure`, поэтому обработчик ошибок не может взять `routeTemplateOf`, а вторая рукописная
копия «как называется этот маршрут» — ровно тот дрейф, ради которого общий помощник и существует.
Сегодня 429 производит только ограничитель; появление второго источника должно разделить метрику,
а не переопределить её смысл — это записано у места вызова.

**Наблюдение о зависимости:** `prom-client` не выпускался с июня 2024. API у него маленький и
стабильный, он остаётся стандартом де-факто, но по правилу зависимостей признак заброшенности
зафиксирован. Альтернатива, если понадобится, — метрики OpenTelemetry, которые придут вместе с
трассировкой в STORY-009-04.


# STORY-009-03 — prom-client, /metrics и RED-метрики

**Как** администратор системы **я хочу** метрики частоты, ошибок и длительности запросов **чтобы**
видеть деградацию до жалоб пользователей и подтверждать соблюдение целевых p95.

## Acceptance (Given/When/Then)

- **Given** обработанный запрос **When** смотрю `/metrics` **Then** увеличен счётчик `http_requests_total{method,route,status}` и записана гистограмма `http_request_duration_seconds{method,route}`.
- **Given** запрос к `/api/v1/tasks/550e8400-…` **When** пишется метрика **Then** значение метки `route` — шаблон `/api/v1/tasks/:id`, а не URL с идентификатором; тест проверяет отсутствие взрыва кардинальности.
- **Given** endpoint `/metrics` **When** к нему обращается анонимный клиент **Then** доступ закрыт (basic-auth из конфигурации либо ограничение по сети); открытие метрик наружу без защиты невозможно по умолчанию.
- **Given** работающий процесс **When** смотрю `/metrics` **Then** присутствуют дефолтные метрики Node (heap, лаг event loop, GC) и метрики пула БД (`db_pool_active`, `db_pool_idle`).
- **Given** будущие очереди **When** смотрю каталог метрик **Then** имена `bullmq_jobs_total`, `bullmq_job_duration_seconds`, `bullmq_queue_depth`, `outbox_lag_seconds` зарезервированы и задокументированы (регистрируются соответствующими эпиками).
- **Given** метрика ошибок аутентификации **When** срабатывает rate limiting **Then** увеличивается `auth_rate_limited_total{endpoint}`.
- **Given** отключённые метрики (`METRICS_ENABLED=false`) **When** приложение работает **Then** endpoint отсутствует и накладных расходов нет.
- **Given** содержимое метрик **When** его читают **Then** в метках нет персональных данных, email, идентификаторов пользователей и организаций.
