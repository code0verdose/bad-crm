# STORY-010-03 — Вход через storageState и фикстуры под ролью

**Как** разработчик Bad CRM **я хочу** запускать сценарий сразу под нужной ролью **чтобы** не
тратить по 3 секунды на прокликивание формы логина в каждом из десятков будущих тестов.

## Acceptance (Given/When/Then)

- **Given** глобальная подготовка прогона **When** она выполняется **Then** для каждой роли (владелец, администратор, тимлид, разработчик) в обеих организациях один раз выполняется вход через API, и состояние сессии сохраняется в файл `storageState`.
- **Given** фикстура `test.use({ storageState: asOwnerOfOrgA })` **When** сценарий стартует **Then** пользователь уже аутентифицирован: форма логина не открывается, первая же навигация ведёт на защищённый маршрут.
- **Given** истёкшее состояние сессии между прогонами **When** сценарий стартует **Then** подготовка перевыпускает `storageState`, а не падает с непонятным редиректом на `/login`.
- **Given** тест, проверяющий саму форму логина **When** он выполняется **Then** он запускается без `storageState` (анонимный контекст) — это единственное место, где форма прокликивается.
- **Given** сценарии под разными ролями **When** они выполняются параллельно **Then** их состояния не смешиваются: у каждой роли отдельный файл состояния и отдельный browser context.
- **Given** refresh-cookie в `storageState` **When** файл сохраняется **Then** он размещается во временном каталоге прогона, попадает в `.gitignore` и не выгружается в артефакты CI.
- **Given** сценарий, которому нужен «свежий» пользователь **When** он выполняется **Then** доступна фикстура, создающая пользователя через API и удаляющая его после теста.

## Задачи

- [ ] Написать тесты первыми: `packages/e2e/tests/auth/storage-state.spec.ts` (под ролью пользователь сразу аутентифицирован; анонимный контекст видит `/login`), `tests/auth/roles-isolation.spec.ts` (контексты ролей не смешиваются).
- [ ] Реализовать `packages/e2e/global-setup.ts`: вход через API для каждой роли, сохранение `storageState` во временный каталог прогона.
- [ ] Реализовать `packages/e2e/fixtures/auth.fixture.ts` — типизированные фикстуры `asOwnerOfOrgA`, `asAdminOfOrgA`, `asDeveloperOfOrgA`, `asOwnerOfOrgB` и т. д.
- [ ] Реализовать проверку валидности сохранённого состояния и его перевыпуск при устаревании.
- [ ] Реализовать фикстуру создания и удаления временного пользователя через публичный API.
- [ ] Добавить каталог состояний в `.gitignore` и исключить его из артефактов CI.
- [ ] Описать в `docs/runbooks/e2e.md`, как выбрать роль для нового сценария.
