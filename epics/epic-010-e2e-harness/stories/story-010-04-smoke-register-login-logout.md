# STORY-010-04 — Smoke: регистрация → вход → оболочка → выход

**Как** владелец инсталляции **я хочу** автоматическую проверку основного сценария M1 **чтобы** не
выпустить сборку, в которой невозможно завести организацию или войти в систему.

## Acceptance (Given/When/Then)

- **Given** чистое окружение **When** сценарий проходит регистрацию организации с уникальным `slug` **Then** после отправки формы пользователь оказывается в оболочке приложения на `/dashboard`, имя организации отображается в интерфейсе.
- **Given** зарегистрированный пользователь **When** он выходит и входит снова по email и паролю **Then** он снова попадает в оболочку; страница входа не показывается после успешной аутентификации.
- **Given** неверный пароль **When** он введён **Then** отображается сообщение об ошибке, привязанное к форме; пользователь остаётся на `/login`; сообщение не раскрывает, существует ли такой email.
- **Given** аутентифицированный пользователь **When** он нажимает «Выйти» **Then** он попадает на `/login`, а попытка вернуться назад по истории браузера снова приводит к `/login`, а не к закешированной оболочке.
- **Given** перезагрузка страницы под аутентифицированным пользователем **When** она выполняется **Then** сессия восстанавливается, экран логина не мигает.
- **Given** экраны `/login` и оболочки **When** выполняется автоматический аудит axe **Then** нарушений уровня A и AA нет.
- **Given** переключатель языка на `/login` **When** выбираю русский, затем английский **Then** подписи формы меняются; сценарий проверяет обе локали по ключам, а не по конкретному тексту в коде теста.
- **Given** прогон в сетевой песочнице без интернета **When** сценарий выполняется **Then** он проходит полностью — внешних запросов приложение не делает.

## Задачи

- [ ] Реализовать page objects: `pages/login.page.ts`, `pages/register.page.ts`, `pages/app-shell.page.ts` с локаторами по ролям и `data-testid`, а не по текстам.
- [ ] Реализовать генерацию уникальных `slug`/email для каждого прогона регистрации, чтобы сценарий был повторяемым.
- [ ] Подключить `@axe-core/playwright` и настроить падение на нарушениях A/AA.
- [ ] Реализовать проверку возврата по истории браузера после выхода.
- [ ] Проверить сценарий в режиме без исходящего интернета и зафиксировать это в конфигурации CI-джобы.
