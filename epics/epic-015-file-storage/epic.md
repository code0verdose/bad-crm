# EPIC-015 — Файловое хранилище

## Зачем (ценность)

Пункт 10 ТЗ: «хранилище файлов — общее, по проектам, личное, с доступами и ролями». Это не отдельная
функция, а инфраструктура: вложения задач (M3), картинки в документах и базе знаний (M4), файлы в
чате (M5), аватары сотрудников (M2), вложения контрактов и инвойсов (M9) — всё физически невозможно
без файлового слоя. Поэтому он идёт в M2, вместе с правами и проектами.

Архитектурное обещание: **тело файла никогда не проходит через процесс API**
([ADR-0015](../../docs/architecture/adr/0015-s3-file-storage-presigned-urls.md)). Загрузка и
скачивание идут напрямую в S3/MinIO по короткоживущим presigned-ссылкам, а приложение остаётся
арбитром прав: ссылка выдаётся **только после проверки capability и ACL в момент запроса**.

Одновременно это самая опасная часть M2 по модели угроз: `T-FILE-04` (открытый наружу MinIO) входит
в топ-15 угроз со сроком M2, а `T-FILE-02` / `R-12` (утечка presigned URL) — риск, который нельзя
устранить полностью, только сжать окном TTL, аудитом каждой выдачи и проксированием чувствительных
файлов.

## Scope

### В скоупе

- `FileStoragePort` + адаптер S3/MinIO; приватный бакет, снятая анонимная policy, запрет листинга,
  preflight-проверка публичности при старте.
- Загрузка: `POST /files/presign` → PUT напрямую в хранилище → `POST /files/{id}/commit` с
  `HeadObject` (существование, фактический размер и content-type).
- Скачивание: presigned GET с TTL ≤ 300 c, привязкой к методу, ключу и `content-disposition`,
  **только после проверки прав**; проксирование через API для файлов с меткой «чувствительный».
- Скоупы `ORG | PROJECT | PERSONAL | TASK | CHAT | VAULT` и `FileAccessReaderPort` с наследованием
  ACL от папки и проекта.
- `FileFolder` — дерево с materialized path, навигация и перемещение.
- `FileVersion` — неизменяемые версии, история, откат.
- Квоты организации, лимиты размера и whitelist MIME-типов.
- Мягкое удаление, корзина, восстановление, джобы зачистки осиротевших объектов и `pending`-загрузок.

### Вне скоупа

- Антивирусное сканирование в поставке — **принятый риск** (`T-FILE-05`): `scanStatus` есть в модели
  с первого дня, порт `AntivirusPort` объявлен, ClamAV подключается конфигурацией.
- Превью и миниатюры документов/видео — backlog; в M2 только базовые изображения.
- Полнотекстовый поиск по содержимому файлов — [EPIC-024](../epic-024-search-meilisearch/epic.md), M4.
- Шифрование тел файлов на клиенте — [EPIC-033](../epic-033-e2ee-crypto-foundation/epic.md), M7;
  здесь только флаг `isEncrypted` и `scanStatus = SKIPPED` для `scope = VAULT`.
- Дедупликация **между** организациями — запрещена архитектурно (`T-FILE-07`).
- Совместное редактирование файлов, WebDAV, синхронизация с диском — вне 1.0.

## Acceptance (эпик выполнен, когда)

- [ ] Файл невозможно получить без проверки прав: presigned-ссылка выдаётся только после
      успешного `can()` в момент запроса, живёт не дольше 300 c и фиксируется в `AuditLog`.
- [ ] Ключ объекта формирует **сервер** (`org/{organizationId}/…`); клиентский `storageKey`
      игнорируется, префикс тенанта проверяется при commit.
- [ ] Presigned PUT ограничен методом, точным ключом, `content-type` и `content-length-range`;
      повторная запись по существующему ключу отклоняется.
- [ ] `commit` доверяет только `HeadObject`: заявленные клиентом размер и тип не влияют на запись.
- [ ] Бакет приватен, анонимный доступ и листинг сняты, инфраструктурные порты не публикуются;
      preflight отказывает старту при публичном бакете.
- [ ] Отдача всегда `Content-Disposition: attachment` + `nosniff`; inline-рендер `text/html` и
      `image/svg+xml` невозможен.
- [ ] Доступ к файлу наследуется от папки и проекта; личный файл (`scope = PERSONAL`) недоступен
      никому, кроме владельца; отказ — 404, а не 403.
- [ ] Дедупликация работает строго внутри организации; кросс-тенантная запрещена и покрыта тестом.
- [ ] Квоты и лимиты работают: превышение даёт понятную ошибку, а не тихий отказ; `PENDING`-файл не
      отдаётся на скачивание.
- [ ] Мягко удалённый файл не возвращается ни одним репозиторием; корзина позволяет восстановить;
      джоб физического удаления и джоб зачистки сирот покрыты тестами.
- [ ] Isolation-тесты RLS зелёные для `files`, `file_folders`, `file_versions`.

## Зависимости / риски

- **Зависит от:** [EPIC-011](../epic-011-rbac-permissions/epic.md) (capability + ACL),
  [EPIC-014](../epic-014-project-core/epic.md) (`scope = PROJECT` и корень наследования),
  [EPIC-005](../epic-005-multi-tenancy-rls/epic.md) (RLS),
  [EPIC-016](../epic-016-audit-log/epic.md) (аудит выдачи ссылок),
  [EPIC-001](../epic-001-monorepo-and-dev-env/epic.md) (MinIO в compose),
  [EPIC-009](../epic-009-observability/epic.md) (метрики квот и очереди сканирования).
- **Блокирует:** [EPIC-012](../epic-012-employee-management/epic.md) (аватары), M3 (вложения задач),
  M4 (картинки в документах и KB, импорт Obsidian), M5 (файлы чата), M7 (зашифрованные блобы vault),
  M9 (документы контрактов).
- **Риски:**
  - `T-FILE-04` (топ-15, M2) — MinIO/бакет доступен снаружи. Митигация: приватный бакет,
    инфраструктурные порты не публикуются, preflight-проверка, интеграционный тест «анонимный GET
    по ключу → 403».
  - `T-FILE-02` / `R-12` — presigned URL нельзя отозвать. Митигация: TTL ≤ 300 c, выдача после
    проверки прав, маскирование подписи в логах, `Referrer-Policy: no-referrer`, аудит каждой
    выдачи, проксирование чувствительных файлов; остаточный риск `RR-05` задокументирован.
  - `T-FILE-01`, `T-FILE-03` — подмена ключа при commit и presigned PUT без ограничений.
  - `T-FILE-06` — XSS через отдачу HTML/SVG с того же origin.
  - `T-FILE-08` — исчерпание диска брошенными загрузками и сиротами; квоты и джобы зачистки.
  - `R-11` — вложения-сироты при удалении родителя: файл удаляется только доменным сервисом
    каскада в той же транзакции; обратные индексы не дают удалить файл, на который ещё ссылаются.
