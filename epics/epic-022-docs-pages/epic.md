# EPIC-022 — Документы Notion-like

## Зачем (ценность)

Спецификация задачи сегодня живёт в Notion, а задача — в трекере; связь между ними существует только
как ссылка, которую кто-то не забыл вставить. Эпик переносит документы внутрь продукта: блочный
редактор, дерево вложенных страниц, привязка к проекту, версии и шаринг через ту же модель прав, что
и задачи. Ключевое архитектурное обещание — **редакторо-независимое хранение**: контент лежит в
стабильной схеме, а экспорт в Markdown/HTML существует с первого дня, поэтому смена редактора не
превращается в миграцию контента (риск `R-09`).

## Scope

### В скоупе

- Блочный редактор на **BlockNote** (`@blocknote/core`, `@blocknote/react` — MPL-2.0, в allow-list).
  Пакеты `@blocknote/xl-*` дуально лицензированы GPL-3.0 / коммерческая; для AGPL-3.0-проекта
  применима ветка GPL-3.0, и **каждый подключённый `xl`-пакет фиксируется отдельной строкой в
  ADR-0012** с указанием лицензии. Пакет вне ADR не попадает в сборку (проверка лицензий в CI).
- Хранение контента: `DocPage.content` — **один JSONB** со стабильной схемой и полем версии
  (`{"v":1,…}`), валидируемой Zod на границе; не внутренний формат вендора.
- Дерево страниц: `parentPageId`, materialized `path` (`.uuid1.uuid2.`), `depth`, `orderKey`
  (fractional index); перенос поддерева одним `UPDATE … replace(path, old, new)`.
- Обложки и иконки страницы: `icon` (эмодзи/символ) и обложка через `File` из EPIC-015.
- Версии: `DocPageVersion` (снапшот на каждое сохранение, `changeSummary`, автор), просмотр истории
  `/docs/$docId/history`, восстановление версии за `doc:restore_version`.
- **Оптимистичная блокировка**: сохранение с устаревшей версией → 409 и явный merge-UX
  (`T-KNOW-06`), потерянные правки восстановимы из `DocPageVersion`.
- **Экспорт в Markdown и HTML с первого дня** + импорт Markdown в документ; round-trip-тесты на
  наборе документов со всеми поддерживаемыми типами блоков.
- Привязка документа к проекту (`projectId?`), список `/docs` и `/projects/$projectId/docs` с
  фильтрами в URL, шаринг `/docs/$docId/share` через `ResourceAcl`.
- Шаблоны страниц: набор преднастроенных документов (спецификация, ADR, retro, meeting notes),
  создание страницы из шаблона.
- Комментарии к документу через полиморфный `Comment` (`entityType = DOC_PAGE`) из EPIC-020, якоря
  на стабильные `id` блоков внутри JSON.
- Санитизация и рендер: `rehype-sanitize`-эквивалент для рендера, whitelist протоколов
  (`http`, `https`, `mailto`), CSP без `unsafe-inline`, запрет исходящих HTTP-запросов из рендера.
- Мягкое удаление и корзина документа.

### Вне скоупа

- База знаний в Markdown, wiki-links и граф — [EPIC-023](../epic-023-knowledge-base/epic.md).
- Поиск по документам — [EPIC-024](../epic-024-search-meilisearch/epic.md).
- Совместное редактирование (Yjs/CRDT), курсоры участников — backlog 1.0 (PRD Won't).
- Публичная публикация документа наружу организации — backlog (публичные клиентские порталы).
- Материалы и онбординг поверх документов — [EPIC-040](../epic-040-onboarding-materials/epic.md) (M8).
- Живое обновление документа по сокету — вне 1.0; в M5 обновляется только список документов.

## Acceptance (эпик выполнен, когда)

- [ ] Документ создаётся, редактируется, сохраняется и открывается заново без потери форматирования
      на корпусе из всех поддерживаемых типов блоков (заголовки, списки, чек-листы, таблица, код,
      цитата, изображение, callout, ссылка на задачу).
- [ ] Экспорт документа в Markdown и в HTML работает с первого релиза эпика; round-trip
      «документ → Markdown → импорт → экспорт» даёт идентичный Markdown на всём корпусе блоков
      (митигация `R-09`). Неподдерживаемые при экспорте блоки перечислены явно и покрыты тестом.
- [ ] Схема `DocPage.content` описана Zod-схемой с версией; документ с неизвестной версией не
      затирается, а открывается в режиме только для чтения с внятным сообщением.
- [ ] ADR-0012 содержит строку на каждый подключённый пакет BlockNote с его лицензией; проверка
      лицензий в CI падает при появлении пакета вне allow-list/ADR (`R-13`, NFR-11).
- [ ] Дерево страниц: создание вложенной страницы, перенос поддерева, изменение порядка внутри
      уровня — `path`/`depth`/`orderKey` пересчитываются корректно; перенос ветки из 50 страниц
      выполняется одним `UPDATE` (тест считает запросы).
- [ ] Одновременное сохранение двумя пользователями: второй получает 409 и диалог разрешения
      конфликта; молчаливой перезаписи нет; обе версии присутствуют в `DocPageVersion`
      (конкурентный тест `doc-optimistic-lock`).
- [ ] История версий показывает автора, время и `changeSummary`; восстановление версии создаёт новую
      версию, а не переписывает историю.
- [ ] Документ, доступный по ACL только его автору, не виден остальным ни в списке, ни по прямой
      ссылке (404), ни в дереве родителя, ни через комментарий; наследование
      `DocPage → родители → Project → Organization` покрыто матричным тестом.
- [ ] `xss-payload-corpus` на редакторе и на импорте Markdown не проходит: `javascript:`/`data:`,
      сырой HTML, `onerror`, SVG — обезврежены (`T-KNOW-01`).
- [ ] Рендер и сохранение документа не выполняют исходящих HTTP-запросов по URL из контента
      (архитектурный тест, `T-KNOW-04`).
- [ ] Открытие документа среднего размера (100 блоков) — p95 < 300 мс на сервере, один `SELECT`
      без рекурсии.

## Модель данных

- Затрагиваемые сущности: `DocPage` **[T]**, `DocPageVersion` **[T]**, `Comment` **[T]**
  (`entityType = DOC_PAGE`), `Attachment` **[T]**, `File` **[T]**, `ResourceAcl` **[T]**
  (`resourceType = DOC_PAGE`), `Project` **[T]**, `OutboxEvent` **[T]**, `AuditLog` **[T]**.
- Индексы: `idx_doc_pages_org_parent_order (organization_id, parent_page_id, order_key) WHERE
  deleted_at IS NULL`; `idx_doc_pages_path (organization_id, path text_pattern_ops)`;
  `idx_doc_pages_search GIN (search_vector)`; `uq_doc_page_versions (doc_page_id, version)`.
- Контент — один JSONB, не таблица блоков: документ читается и пишется целиком (решение и его цена
  зафиксированы в data-model §5). Ссылка на блок — стабильный `id` внутри JSON, а не строка в БД.
- **Пробел модели:** у `DocPage` нет поля `version Int` для оптимистичной блокировки — есть только
  `DocPageVersion`. Требуется добавить `DocPage.version` (или `contentUpdatedAt` как ETag),
  иначе `T-KNOW-06` не закрывается.
- **Пробел модели:** нет поля обложки (`coverFileId?`) — в модели присутствует только `icon`.
  Требуется добавить `DocPage.coverFileId?` → `File`.
- **Пробел модели:** шаблоны страниц не имеют сущности. На MVP — константы в коде
  (`units/doc/model/constants/doc-templates.constant.ts`); пользовательские шаблоны потребуют
  `DocPageTemplate` **[T]**.
- **Пробел модели:** экспорт/импорт Markdown не имеет собственной сущности задания. Для одиночного
  документа это синхронная операция; массовый экспорт пространства документов, если понадобится,
  потребует джоба по образцу `KbImportJob`.

## Права

- Ключи из каталога §3.6: `doc:read` (`VIEWER`), `doc:create` (`EDITOR`), `doc:update` (`EDITOR`),
  `doc:move` (`EDITOR`), `doc:delete` (`EDITOR`), `doc:publish` (`EDITOR`),
  `doc:view_history` (`VIEWER`), `doc:restore_version` (`EDITOR`), `doc:export` (`VIEWER`),
  `doc:share` (`MANAGER`, **dangerous**), `doc:manage_acl` (`MANAGER`, **dangerous**).
- Сопутствующие: `comment:*` (§3.5) для обсуждения документа; `file:upload`/`file:read` (§3.8) для
  изображений и обложек; `acl:read`/`acl:grant`/`acl:revoke` (§3.3).
- ACL-уровни и наследование: `DocPage → родительские DocPage (рекурсивно по materialized path) →
  Project → Organization`. Ближайшая явная запись побеждает; `NONE` на странице скрывает и её
  поддерево. Комментарии и вложения документа собственного ACL не имеют — наследуют страницу.
- **Закрыто (2026-07-26):** `doc:import` **уже в каталоге** ([`permission-model.md`](../../docs/security/permission-model.md) §3:
  ресурс `doc`, ACL `EDITOR`, не опасное, домен `knowledge`) — по аналогии с `kb_space:import`.

## Зависимости / риски

- Зависит от: EPIC-014 (проект как родитель), EPIC-015 (файлы для изображений и обложек),
  EPIC-011 + EPIC-021 (модель прав и её применение к дереву), EPIC-020 (полиморфные комментарии и
  вложения с проверкой родителя), EPIC-007 (дизайн-система), EPIC-002 (проверка лицензий в CI).
- Блокирует: EPIC-024 (индексация документов), EPIC-040 (материалы и онбординг, M8),
  EPIC-041/EPIC-044 (документы контракта и сводки созвонов, M9).
- Риски:
  - `R-09` — **ключевой риск эпика**: смена редактора Docs. Митигация — редакторо-независимая схема
    контента, экспорт/импорт Markdown с первого дня, round-trip-тесты, ADR-0012 до старта работ.
  - `R-13` / NFR-11 — лицензионная чистота: `@blocknote/xl-*` под GPL-3.0; каждый пакет — строка в
    ADR-0012 и в allow-list, иначе мерж блокируется.
  - `T-KNOW-01` — stored XSS через контент документа: санитайзер, whitelist протоколов, CSP.
  - `T-KNOW-04` — SSRF через удалённые ресурсы в документе: сервер не загружает внешние URL из
    контента по умолчанию.
  - `T-KNOW-06` — гонка версий: оптимистичная блокировка и merge-UX.
  - `T-KNOW-07` — массовая эксфильтрация через экспорт: `doc:export` логируется в `AuditLog`,
    лимиты объёма и частоты.
