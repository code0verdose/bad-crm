# EPIC-026 — Чат — ядро

## Зачем (ценность)

Обсуждение проекта живёт в отдельном мессенджере, поэтому контекст рвётся ровно там, где он нужнее
всего: решение принято в треде, а задача о нём не знает. Эпик переносит коммуникацию внутрь рабочего
контекста — публичные, приватные и проектные каналы, личные и групповые диалоги, история с курсорной
пагинацией и надёжная отправка, которая не двоит сообщения при обрыве сети. Права на канал
наследуются от проекта, поэтому доступ к обсуждению не нужно администрировать отдельно от доступа к
работе.

## Scope

### В скоупе

- `Channel` всех видов: `PUBLIC` (виден и доступен для входа всем сотрудникам), `PRIVATE`
  (только по приглашению), `PROJECT` (привязан к `projectId`, доступ наследуется от проекта),
  `DM` и `GROUP_DM`.
- `dmKey` — детерминированный ключ из отсортированной пары `userId` с уникальным индексом: два
  человека не создадут два параллельных диалога, кликнув друг на друга одновременно.
- `ChannelMember`: вступление в публичный канал, приглашение в приватный, выход, роль
  `MEMBER | ADMIN`, `notificationLevel ALL | MENTIONS | NONE`, `mutedUntil`, `leftAt`.
- Отправка и отображение сообщений: `Message` (`body Json` + `plainText`, версия схемы в JSONB),
  автор строго из сессии, `systemKind` от клиента не принимается вовсе.
- **Идемпотентная отправка через `clientNonce`**: клиент генерирует nonce до отправки, уникальный
  индекс `(channel_id, author_id, client_nonce)` превращает ретрай после таймаута или
  переподключения в конфликт вставки вместо дубля в ленте.
- История с **курсорной (keyset) пагинацией** `WHERE created_at < $cursor` — не `OFFSET`;
  бесконечная лента вверх, переход к сообщению по ссылке (`?msg=`), «новые сообщения» разделителем.
- Поиск по каналам и сообщениям через `SearchPort` (EPIC-024) с фильтрацией по членству —
  приватный канал не всплывает в выдаче постороннему.
- Архивация канала (`isArchived`) и удаление с каскадом по сообщениям, вложениям и индексу
  (через outbox).
- Права на каналы через `ResourceAcl` с наследованием от проекта; для `DM`/`GROUP_DM` цепочки нет —
  доступ определяется исключительно членством.
- Список каналов с сортировкой по активности (`lastMessageAt`), поиск канала, счётчик непрочитанного
  из `ChannelMember.unreadCount` (сам механизм чтения — EPIC-027).
- Экраны `/chat`, `/chat/$channelId`, `/chat/$channelId/info` (вкладки about/members/files/pins).
- Санитизация тела сообщения и whitelist протоколов ссылок.

### Вне скоупа

- Реакции, редактирование с историей, треды как продукт, read receipts, presence, счётчики
  прочитанного и упоминания — [EPIC-027](../epic-027-chat-rich-messaging/epic.md)
  (поле `parentMessageId` заводится здесь, UX тредов — там).
- Вложения и изображения в сообщениях — [EPIC-027](../epic-027-chat-rich-messaging/epic.md).
- Центр уведомлений — [EPIC-028](../epic-028-notifications/epic.md).
- Транспорт, комнаты, авторизация подписки — [EPIC-025](../epic-025-realtime-infrastructure/epic.md).
- Голосовые сообщения и созвоны — backlog 1.0 (PRD Won't).
- Превью (unfurl) ссылок на задачи и документы — [EPIC-027](../epic-027-chat-rich-messaging/epic.md).

## Acceptance (эпик выполнен, когда)

- [ ] Каналы всех пяти видов создаются и открываются; проектный канал автоматически доступен
      участникам проекта без отдельной выдачи прав, и недоступен постороннему (404).
- [ ] Два пользователя, одновременно открывшие диалог друг с другом, попадают в **один** канал
      (`uq_channels_dm_key`); конкурентный тест на параллельное создание зелёный.
- [ ] Повторная отправка одного сообщения (ретрай после таймаута, переподключение сокета, двойной
      клик) не создаёт дубль: сервер отвечает исходным сообщением по `clientNonce`; тест
      `idempotent-send` с тремя одновременными попытками.
- [ ] История канала на 10 000 сообщений листается курсором вверх без `OFFSET`; p95 запроса страницы
      < 300 мс по индексу `idx_messages_channel_created`; переход по прямой ссылке на сообщение
      подгружает окно вокруг него.
- [ ] Приватный канал **не утекает вторичными путями** (`T-CHAT-02`): ни через поиск, ни через
      счётчик непрочитанного, ни через список каналов, ни через упоминание, ни через прямую ссылку —
      e2e `private-channel-invisible-everywhere`.
- [ ] `authorId` и `systemKind` из тела запроса игнорируются; входные схемы `.strict()`;
      системное сообщение невозможно подделать клиентом (`T-CHAT-03`).
- [ ] Выход из канала и исключение участника немедленно прекращают доставку событий (совместно с
      EPIC-025) и убирают канал из списка; история остаётся доступна только если канал публичный.
- [ ] Архивация скрывает канал из активного списка, запрещает новые сообщения и сохраняет историю
      для тех, у кого есть доступ; удаление канала порождает outbox-событие, после которого поиск и
      вложения недоступны (`T-CHAT-07`).
- [ ] Поиск по сообщениям возвращает только сообщения каналов, членом которых является
      пользователь; проверяется в `search-acl-isolation` вместе с EPIC-024.
- [ ] `xss-payload-corpus` для чата не проходит: `javascript:`-ссылки, сырой HTML, поддельные
      «системные» сообщения (`T-CHAT-04`).
- [ ] p95 доставки сообщения отправитель → получатель < 400 мс при 200 одновременных соединениях
      (совместный критерий с EPIC-025).

## Модель данных

- Затрагиваемые сущности: `Channel` **[T]**, `ChannelMember` **[T]**, `Message` **[T]**,
  `ResourceAcl` **[T]**, `Project` **[T]**, `OutboxEvent` **[T]**, `AuditLog` **[T]**,
  `User.lastSeenAt` **[T]**.
- Индексы: `idx_messages_channel_created (organization_id, channel_id, created_at DESC)` — главный
  индекс подсистемы, пагинация keyset; `uq_messages_client_nonce (channel_id, author_id,
  client_nonce)`; `uq_channels_dm_key (organization_id, dm_key) WHERE dm_key IS NOT NULL`;
  `idx_channels_org_project`, `idx_channels_org_activity (…) WHERE NOT is_archived`;
  `uq_channel_members (channel_id, user_id)`;
  `idx_messages_thread (…) WHERE parent_message_id IS NOT NULL`;
  `idx_messages_search GIN (to_tsvector('simple', plain_text))`.
- `Message.body` — JSONB с версией схемы; `plainText` вынесен отдельной колонкой, потому что по нему
  ищут и сортируют (правило «в JSONB не кладём то, по чему фильтруем»).
- **Пробел модели:** `ResourceAcl.resourceType` не содержит `CHANNEL`, хотя permission-model
  описывает наследование `Channel → Project → Organization` и права `channel:*` требуют ACL-уровня.
  Требуется расширить enum `AclResourceType` значением `CHANNEL`, иначе точечная выдача доступа к
  каналу невыразима.
- **Пробел модели:** нет закреплённых сообщений, хотя право `message:pin` в каталоге есть и вкладка
  `pins` описана в UX. Требуется `Message.pinnedAt`/`pinnedById` либо таблица `MessagePin` **[T]**.
- **Пробел модели:** у `Channel` нет `deletedAt` (мягкое удаление есть у `Message`, но не у канала).
  Требуется решение: мягкое удаление канала или физическое с каскадом; текущее допущение эпика —
  архивация как основной путь, удаление физическое с outbox-каскадом и подтверждением.
- `memberCount` и `lastMessageAt` — денормализованные поля, допускают расхождение и периодически
  пересчитываются фоном.

## Права

- Ключи из каталога §3.12: `channel:read` (`VIEWER`), `channel:read_any` (**dangerous**),
  `channel:create`, `channel:update` (`EDITOR`), `channel:join_public`,
  `channel:manage_members` (`MANAGER`), `channel:archive` (`MANAGER`),
  `channel:delete` (`MANAGER`, **dangerous**), `channel:export` (`MANAGER`, **dangerous**),
  `message:create` (`COMMENTER`), `message:update_own` (`COMMENTER`),
  `message:delete_own` (`COMMENTER`), `message:delete_any` (`EDITOR`, **dangerous**),
  `message:pin` (`EDITOR`), `message:search` (`VIEWER`).
- Сопутствующие: `project:read` (`VIEWER`) — для проектных каналов; `acl:grant`/`acl:revoke` (§3.3).
- ACL-уровни и наследование: `Channel → Project → Organization` для `PROJECT`-каналов;
  для `PUBLIC` — `implicitLevel` уровня организации (`VIEWER` любому сотруднику + `channel:join_public`);
  для `PRIVATE` — только явные записи ACL и членство; для `DM`/`GROUP_DM` **наследования нет**,
  доступ определяется исключительно `ChannelMember` (это зафиксировано в permission-model).
  `channel:read_any` — административный обход, всегда пишется в `AuditLog`.
- Отсутствующих ключей нет.

## Зависимости / риски

- Зависит от: EPIC-025 (транспорт, комнаты, авторизация подписки), EPIC-014 (проект как родитель
  канала), EPIC-011 + EPIC-021 (модель прав и цепочки), EPIC-024 (поиск по сообщениям),
  EPIC-005 (RLS), EPIC-007 (дизайн-система, бесконечная лента).
- Блокирует: EPIC-027 (богатые сообщения строятся на этой модели),
  EPIC-028 (упоминания и события каналов — источник уведомлений),
  EPIC-044 (обсуждение созвонов, M9).
- Риски:
  - `T-CHAT-02` — **ключевой риск эпика**: приватный канал утекает вторичными путями (поиск,
    счётчики, уведомления, превью). Митигация: единая функция видимости каналов, `visibleTo` в
    поисковом документе, уведомления только членам, e2e на все вторичные пути.
  - `T-CHAT-01` — подписка на чужую комнату (закрывается EPIC-025, здесь — проверка на уровне
    политики канала).
  - `T-CHAT-03` — подделка автора и системных сообщений: актор из сессии, `.strict()`-схемы.
  - `T-CHAT-04` — stored XSS и фишинг: общий санитайзер, whitelist протоколов.
  - `T-CHAT-07` — данные удалённого канала: каскад через outbox по сообщениям, вложениям и индексу.
  - `R-18` — сравнение со Slack не в нашу пользу: реализуем ядро сценариев персоны (проектное
    обсуждение рядом с работой), а не паритет функций; расширение — только через ADR.
