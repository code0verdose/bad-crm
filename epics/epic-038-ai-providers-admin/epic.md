# EPIC-038 — Настройка AI-провайдеров администратором

## Зачем (ценность)

Прямая боль персоны P5: настройка AI-провайдера не должна требовать правки конфигов и рестарта
контейнера. Bad CRM — self-hosted продукт с моделью **BYOK** (bring your own key): централизованного
биллинга за токены нет, каждая организация приносит свои ключи и сама решает, куда уходят её данные —
в Anthropic, в OpenAI, в OpenRouter или в локальный OpenAI-совместимый сервер в собственной сети.

Эпик даёт администратору экран, на котором подключение проверяется до того, как им начнут
пользоваться, а ключ после сохранения не показывается больше никогда. Это фундамент для
[EPIC-039](../epic-039-ai-assistant/epic.md): ассистент не должен знать, как устроен провайдер, — он
обращается к порту.

## Scope

### В скоупе

- **`AIProvider`**: `kind ANTHROPIC | OPENAI | OPENAI_COMPAT | OPENROUTER`, `name`, `baseUrl?` (обязателен для `OPENAI_COMPAT`), `apiKeyEnc` + `apiKeyTail` (последние 4 символа), `modelChat`, `modelEmbed?`, `maxTokens`, `isActive`, `isDefault`, `isEmbeddingsDefault`, `monthlyBudgetMicros?`.
- **Админ-UI** `/admin/ai-providers` со списком и карточкой (`connection | models | limits`): пресеты по типу провайдера (готовые `baseUrl`, набор моделей, формат ключа), подсказки «где взять ключ» и «какая модель для чего», явное различие моделей чата и эмбеддингов.
- **Test-connection** — кнопка «Проверить подключение» с реальным запросом и **замером времени до первого токена**: администратор видит не только «работает», но и насколько это будет отзывчиво для пользователей.
- **`list-models`** через нативный endpoint провайдера (там, где он есть) с фолбэком на пресет-список; выбор модели из реального перечня, а не из свободного текстового поля.
- **Раздельные дефолты**: `isDefault` (чат) и `isEmbeddingsDefault` (эмбеддинги) — разные решения (чат в облаке, эмбеддинги на локальном сервере). Уникальность гарантируют частичные индексы `WHERE is_default` и `WHERE is_embeddings_default`.
- **`provider-factory.ts`** и `GetDecryptedAIProviderUseCase`: единственная точка расшифровки ключа и создания клиента; **fallback-цепочки по фичам** (чат → дефолтный чат-провайдер → первый активный; эмбеддинги → дефолтный embed-провайдер → отказ с внятной ошибкой, а не молчаливое использование чат-модели).
- **Шифрование ключей AES-256-GCM** ключом приложения из окружения, `algoVersion`, перешифровка фоновым джобом при ротации; **ключ никогда не возвращается в API** — наружу отдаётся только `apiKeyTail` («sk-…f3a9»), «показать ключ» не существует, только «заменить».
- **`AIUsageDaily`** — преагрегат расхода (запросы, токены, стоимость, ошибки) по провайдеру, модели и пользователю; экран расхода для администратора.
- Бюджет организации (`monthlyBudgetMicros`) и предупреждение при достижении 80 % (триггер эскалации риска **R-07**); жёсткое поведение при исчерпании реализуется в [EPIC-039](../epic-039-ai-assistant/epic.md).
- **Ассистент по умолчанию выключен**: отсутствие настроенного провайдера — нормальное состояние системы, при котором ни один основной сценарий не деградирует.

### Вне скоупа

- Треды, сообщения, стриминг, RAG, tool-calls, rate limiting по пользователю — [EPIC-039](../epic-039-ai-assistant/epic.md).
- Локальный инференс в поставке (ollama/llama.cpp как сервис compose) — вне 1.0; `OPENAI_COMPAT` позволяет подключить его самостоятельно.
- Тонкая настройка промптов и системных инструкций на уровне организации — [EPIC-039](../epic-039-ai-assistant/epic.md).
- Централизованный биллинг и тарификация AI внутри продукта — **вне продукта** (`prd.md`).

## Acceptance (эпик выполнен, когда)

- [ ] Провайдер каждого из четырёх типов подключается через UI без правки конфигов и без рестарта приложения.
- [ ] Test-connection выполняет реальный запрос, показывает результат и **время до первого токена**; неуспех даёт диагностируемую ошибку (неверный ключ / недоступен хост / модель не найдена), а не «что-то пошло не так».
- [ ] `list-models` отдаёт перечень из нативного endpoint провайдера; при его отсутствии — пресет-список с явной пометкой источника.
- [ ] API **никогда** не возвращает `apiKey` целиком ни на одном эндпоинте: контрактный тест сериализаторов + `log-redaction-corpus` не находят ключ в ответах, логах, трейсах и метриках.
- [ ] Ключ хранится только зашифрованным (AES-256-GCM); ротация ключа приложения перешифровывает колонки фоновым джобом без простоя; `algoVersion` учитывается.
- [ ] Частичные уникальные индексы работают: попытка сделать второй `isDefault` или второй `isEmbeddingsDefault` в организации отклоняется базой.
- [ ] `provider-factory` — **единственное** место расшифровки ключа; архитектурный тест доказывает, что `apiKeyEnc` не читается больше нигде.
- [ ] Fallback-цепочки покрыты табличным тестом: чат без дефолта, эмбеддинги без дефолта, все провайдеры неактивны, провайдер удалён при живых тредах — в каждом случае поведение детерминировано и объяснено пользователю.
- [ ] При отсутствии настроенных провайдеров приложение работает полностью; AI-элементы интерфейса отсутствуют, а не показывают ошибку (NFR-9).
- [ ] Расход виден администратору по организации, провайдеру, модели и пользователю; `costMicroUsd` фиксируется **в момент запроса** и не пересчитывается задним числом по текущему прайсу.
- [ ] Изменение конфигурации провайдера и любой доступ к ключу пишутся в `AuditLog` с повышенной `severity`.
- [ ] Появление ключа в чьём-либо сообщении или логе обрабатывается по правилу учёта утечек (маскированная запись + инструкция ротации).
- [ ] Кросс-тенантный негативный тест: провайдер и расход чужой организации недоступны.

## Модель данных

- Затрагиваемые сущности: `AIProvider` [T], `AIUsageDaily` [T], `AuditLog` [T], `Organization` [T], `User` [T].
- Новые поля/таблицы:
  - `AIProvider.algoVersion` — **отсутствует**; требуется для ротации ключа приложения (та же проблема, что у `GithubInstallation` в [EPIC-037](../epic-037-github-integration/epic.md)); без него перешифровка неотличима от порчи данных.
  - `AIProvider.lastCheckedAt`, `lastCheckStatus`, `lastCheckLatencyMs` — **отсутствуют**; результат test-connection негде хранить, а показывать его в списке нужно.
  - `AIProvider.pricePromptMicros` / `priceCompletionMicros` — **отсутствуют**. `costMicroUsd` «считается на нашей стороне из токенов и прайса модели», но источник прайса в модели не описан: он либо захардкожен в коде (тогда для `OPENAI_COMPAT` и локальных моделей всегда ноль), либо задаётся администратором. Требуется решение до реализации учёта расхода.
- Валюта `AIUsageDaily`/`AIMessage` прибита к USD — единственное осознанное исключение из правила «сумма всегда с валютой», зафиксировано в `data-model.md`.
- Уникальность дефолтов — частичными индексами, а не логикой приложения.
- Открытый вопрос №5 `data-model.md` (размерность эмбеддингов жёстко `vector(1536)`): выбор `modelEmbed` **ограничен моделями с размерностью 1536**, иначе запись в `Embedding` невозможна. Ограничение обязано быть выражено в UI как фильтр списка моделей, а не как ошибка после сохранения.

## Права

- Новые ключи (из каталога [`permission-model.md` §3.15](../../docs/security/permission-model.md)): `ai:configure_providers` (**опасное**), `ai:manage_budget` (**опасное**), `ai:view_usage`.
- Требуемые ACL-уровни: все три ключа организационные (ACL `—`) — провайдер настраивается на уровне организации, а не проекта.
- Опасные: `ai:configure_providers`, `ai:manage_budget`. Оба требуют подтверждения в UI и записи в `AuditLog` с повышенной `severity`; в шаблон кастомной роли «по умолчанию» не входят.
- Отдельно: `ai:view_usage` намеренно **не опасное** — видеть расход полезно и безопасно; управлять бюджетом — нет.

## Зависимости / риски

- Зависит от: [EPIC-011](../epic-011-rbac-permissions/epic.md), [EPIC-016](../epic-016-audit-log/epic.md), [EPIC-009](../epic-009-observability/epic.md) (маскирование, метрики), [EPIC-003](../epic-003-server-skeleton-and-api-contract/epic.md) (порты и адаптеры — `AIProviderPort`), [EPIC-007](../epic-007-design-system/epic.md).
- Блокирует: [EPIC-039](../epic-039-ai-assistant/epic.md), [EPIC-044](../epic-044-calls-and-calendar/epic.md) (AI-генерация сводки созвона).
- Риски:
  - **`T-AI-05`** (данные уходят внешнему провайдеру) — здесь митигируется на уровне выбора: `OPENAI_COMPAT` с локальным `baseUrl` позволяет вообще не выпускать данные наружу; интерфейс обязан явно называть, куда уходит трафик каждого провайдера.
  - **R-07** (неконтролируемая стоимость AI) — бюджет и учёт расхода закладываются здесь, жёсткий стоп — в [EPIC-039](../epic-039-ai-assistant/epic.md).
  - **Утечка ключа** — правило учёта утечек: любой замеченный ключ фиксируется маскированно с инструкцией ротации; ключ не логируется никогда, `apiKeyTail` — единственное, что видно.
  - **SSRF через `baseUrl`** — `OPENAI_COMPAT` принимает адрес от администратора; требуется `ssrf-blocklist` (запрет метаданных облака, localhost вне явного allow, приватных диапазонов без подтверждения) и явное предупреждение в UI. Отдельного `T-*` ID для этого вектора в модели угроз **нет** — требуется завести (`T-AI-10` или в разделе `integration`).
  - Организационный: соблазн «показать ключ, чтобы проверить» — прямое нарушение; в интерфейсе есть только «заменить».
