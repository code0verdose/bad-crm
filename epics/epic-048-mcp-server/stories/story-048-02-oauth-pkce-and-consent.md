# STORY-048-02 — OAuth 2.1 с PKCE и экран согласия

**Как** пользователь **я хочу** подключить свой удалённый агент к установке, явно увидев и одобрив,
что ему разрешено **чтобы** доступ был выдан осознанно, ограниченно и отзываемо.

## Acceptance (Given/When/Then)

- **Given** зарегистрированный клиент **When** он начинает authorization code flow **Then** обязателен
  PKCE `S256`: запрос без `code_challenge` или с `plain` отвергается.
- **Given** экран согласия **When** пользователь его видит **Then** экран показан **в интерфейсе
  Bad CRM**, в его сессии, и называет: клиента, запрошенный список инструментов, срок действия и
  прямым текстом — что агент действует в пределах его прав и что разрешённое ему действие будет
  исполнено (остаточный риск `RR-08`).
- **Given** выданный токен **When** он предъявляется **Then** он принимается только если `aud`
  совпадает с `resource` этой установки (RFC 8707); токен, выданный другому сервису, отвергается с
  отдельным кодом ошибки, а не «невалидным токеном вообще».
- **Given** установка **When** она обрабатывает MCP-запрос **Then** она **никогда** не пересылает
  полученный токен во внешние вызовы (token passthrough запрещён) — проверяется тестом на исходящие.
- **Given** refresh-токен **When** он использован повторно **Then** отзывается всё семейство, как для
  сессий EPIC-006, и событие попадает в аудит.
- **Given** согласие **When** пользователь его отзывает **Then** следующий вызов инструмента этим
  клиентом отклоняется — без ожидания истечения access-токена и без кеша решения.
- **Given** установка по умолчанию **When** клиент пытается зарегистрироваться динамически (RFC 7591)
  **Then** запрос отклонён; включение DCR требует `mcp:manage_clients` и фиксируется в аудите.
- **Given** попытка входа через этот flow **When** учётные данные неверны **Then** срабатывает
  существующая политика `auth_attempt`, а не отдельный, более щедрый счётчик.

## Задачи

- [ ] Тесты первыми: PKCE обязателен; `aud`-несовпадение отвергается; reuse refresh отзывает
      семейство; отзыв согласия действует немедленно; DCR выключена.
- [ ] `application/platform/use-cases/*`: выдача кода, обмен на токен, refresh с ротацией — поверх
      механизма EPIC-006, без второй реализации.
- [ ] Метаданные сервера авторизации (`/.well-known/oauth-authorization-server`,
      `/.well-known/oauth-protected-resource`) — с обоснованием их публичности в `publicReason`.
- [ ] Экран согласия в клиенте: `units/mcp` + маршрут в `app/routes`, EN + RU.
- [ ] Аудит: выдача согласия, отзыв, обнаружение повторного использования refresh.
- [ ] `docs/api/openapi.yaml` — операции согласия и метаданных (это обычные HTTP-маршруты, в
      allow-list они не входят).

## Definition of Done

- [ ] Тесты написаны первыми (TDD), включая негативные по каждому пункту acceptance
- [ ] Commit-гейт зелёный; `security-auditor` отдельно смотрит на flow целиком
- [ ] EN + RU для экрана согласия; текст про «в пределах ваших прав» переведён и проверен
- [ ] a11y: экран согласия проходит ручной чек-лист (фокус, клавиатура, объявление ошибок)
- [ ] Запись в `docs/brain/`
