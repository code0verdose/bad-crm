# STORY-048-04 — Инструменты чтения и фильтрация списка правами

**Как** разработчик **я хочу** спрашивать своего агента «что у меня в работе» и «сколько я списал на
проект за неделю» **чтобы** не переключаться в интерфейс за фактами, которые он может получить сам.

## Acceptance (Given/When/Then)

- **Given** подключённый агент **When** он вызывает `tasks.search`, `tasks.get`, `docs.search`,
  `time.summary`, `projects.list` **Then** каждый возвращает данные ровно в пределах прав
  пользователя, а решение о доступе принято в use-case, а не в обработчике инструмента.
- **Given** два пользователя с разными ролями **When** оба выполняют `tools/list` **Then** списки
  отличаются **ровно на права**: инструмент без права у пользователя в списке отсутствует.
- **Given** задача из другой организации **When** агент зовёт `tasks.get` с её идентификатором
  **Then** ответ — `resource_not_found`, а не «доступ запрещён» (иначе канал становится оракулом
  существования сущностей).
- **Given** `tasks.search` **When** он отвечает **Then** в ответе нет описания задачи и комментариев:
  список — это заголовки, а выгрузка содержимого делается точечным `tasks.get` с проверкой ACL.
- **Given** `time.summary` **When** он отвечает **Then** значения — в минутах, и ни ставок, ни
  себестоимости, ни сумм в ответе нет ни при каком аргументе.
- **Given** `time.summary` с чужим `userId` **When** у пользователя нет `time:read_team`/`time:read_all`
  **Then** отказ; со своим `userId` — работает при `time:read_own`.
- **Given** любой инструмент поиска **When** в организации есть vault-элементы и защищённые ссылки
  **Then** они не появляются в выдаче ни при каком запросе — потому что типы vault отсутствуют в
  allow-list, а не отфильтрованы.
- **Given** `limit` больше потолка **When** он передан **Then** он приводится к потолку, а не
  исполняется: агент не должен уметь вытянуть весь проект одним вызовом.
- **Given** ответ инструмента **When** он сериализуется **Then** он содержит только поля, объявленные
  схемой в манифесте — тест на отсутствие «лишних» полей.

## Задачи

- [ ] Тесты первыми: `mcp-acts-as-user` на паре ролей; расхождение `tools/list` ровно на права;
      404 на чужой тенант; отсутствие полей вне схемы; потолок `limit`; отсутствие vault в выдаче.
- [ ] Пять инструментов в `presentation/mcp/tools/**` поверх существующих use-case'ов (без новых
      запросов к БД — если нужного use-case нет, он заводится в своём контексте, а не в адаптере).
- [ ] Записи в `docs/api/mcp-tools.yaml` с описаниями, которые читает модель: описание инструмента —
      часть контракта, от него зависит, будет ли он вызван правильно.
- [ ] Фильтрация `tools/list` по правам пользователя и области токена.
- [ ] Удалить временный `system.ping` из STORY-048-01.
- [ ] Прогнать `prompt-injection-corpus` по каналу: на первом срезе ни один вызов не выходит за
      пределы прав, потому что выходить некуда — зафиксировать это как базовую линию.
