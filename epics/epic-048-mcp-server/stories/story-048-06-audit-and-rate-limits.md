# STORY-048-06 — Аудит вызовов и лимиты канала

**Как** администратор организации **я хочу** видеть, что именно сделал внешний агент, и быть уверен,
что он не выест ресурсы установки **чтобы** разбор инцидента был возможен, а работа людей не
страдала от цикла чужой модели.

## Acceptance (Given/When/Then)

- **Given** любой `tools/call` **When** он исполнен, отклонён или упал **Then** в `AuditLog` есть
  запись `mcp.tool_called`: пользователь, клиент, сессия, инструмент, аргументы, результат
  (`ok | denied | failed`), `requestId`.
- **Given** аргументы вызова **When** они пишутся в аудит **Then** записываются только поля,
  объявленные схемой инструмента, и значения проходят тот же редактор секретов, что и логи: поле вне
  схемы в журнал не попадает.
- **Given** пишущий инструмент **When** транзакция откатилась **Then** записи о выполненном действии
  не остаётся, а при недоступном приёмнике аудита — откатывается само действие (fail-closed, как
  STORY-009-06).
- **Given** каталог инструментов **When** добавлен новый **Then** гейт полноты требует, чтобы он
  писал в аудит: инструмент без записи валит сборку, как действие без вызывающего в
  `audit-coverage.test.ts`.
- **Given** агент в цикле **When** он зовёт один инструмент десятки раз в секунду **Then** срабатывает
  политика `mcp_tool_call` (пользователь × инструмент), и бюджет `api_request` при этом **не
  расходуется**: интерфейс живого человека продолжает работать.
- **Given** попытки установить сессии **When** их слишком много **Then** срабатывает `mcp_session`.
- **Given** недоступный Redis **When** приходит вызов инструмента **Then** отказ, а не пропуск
  (fail-closed, как для существующих политик).
- **Given** отказ по лимиту **When** он возвращается агенту **Then** ответ содержит время, через
  которое можно повторить, — иначе модель повторяет немедленно и бесконечно.

## Задачи

- [ ] Тесты первыми: запись на каждый исход; поле вне схемы не попадает в аудит; откат при
      недоступном аудите; лимит не трогает бюджет HTTP; fail-closed при недоступном счётчике.
- [ ] `mcp.tool_called` в `AUDIT_ACTIONS` (`packages/shared/src/audit/audit-action.enums.ts`).
- [ ] `mcp_tool_call` и `mcp_session` в `RATE_LIMIT_POLICIES` с комментарием, объясняющим, почему
      это отдельные политики, а не доля `api_request`.
- [ ] Гейт «каждый инструмент манифеста пишет в аудит» — по образцу `audit-coverage.test.ts`, с
      контролем на непустоту.
- [ ] Метрики: счётчик вызовов по инструменту и по исходу, с меткой **имени инструмента** (закрытое
      множество из манифеста — кардинальность ограничена по построению).

## Definition of Done

- [ ] Тесты написаны первыми (TDD), гейт полноты доказан подсадкой (инструмент без аудита роняет)
- [ ] Commit-гейт зелёный; `production-readiness` на лимиты и метрики
- [ ] Запись в `docs/brain/`
