# STORY-048-08 — Управление доступом: агенты пользователя и надзор администратора

**Как** пользователь **я хочу** видеть, какие агенты подключены к моей учётной записи, и отключать их
одним действием; **как** администратор — видеть то же по организации **чтобы** подозрение на
компрометацию закрывалось за секунды, а не за смену пароля всей команде.

## Acceptance (Given/When/Then)

- **Given** страница «Подключённые агенты» **When** пользователь её открывает **Then** видит: клиента,
  когда выдано согласие, область (список инструментов), когда использовался в последний раз, с какого
  адреса (хеш/подсеть, не полный IP в интерфейсе).
- **Given** подключённый агент **When** пользователь нажимает «Отключить» **Then** согласие и сессии
  отозваны, следующий вызов отклонён немедленно, событие в аудите.
- **Given** администратор с `mcp:read_any_session` **When** он открывает раздел организации **Then**
  видит сессии всех пользователей; **без** этого права раздел недоступен, а попытка обратиться к
  API — `resource_not_found`, а не 403 со списком.
- **Given** администратор с `mcp:revoke_any_session` **When** он отзывает чужую сессию **Then** она
  отозвана, владелец получает уведомление, событие в аудите с повышенной severity (опасное право).
- **Given** администратор с `mcp:manage_tool_policy` **When** он выключает инструмент для роли
  **Then** инструмент исчезает из `tools/list` у всех этой роли и отклоняется при прямом вызове;
  включить инструмент **сверх** прав пользователя политика не может — только сузить.
- **Given** организация **When** администратор выключает MCP целиком **Then** все сессии отозваны, а
  `tools/list` пуст — выключение действует немедленно, а не «до истечения токенов».
- **Given** любой из этих экранов **When** он показывает список **Then** фильтрация выполняется в SQL,
  а `total` считается тем же предикатом (`rules/permissions.mdc`, п. 8).

## Задачи

      выключение канала отзывает сессии; список == построчный `can()`.
- [ ] Сущности `McpClient`, `McpConsent`, `McpSession`, `McpToolPolicy` + миграции с RLS по канону.
- [ ] Use-case'ы: список и отзыв своих (self-service, `ownershipCheckedIn`), список и отзыв чужих
      (право из каталога), политика инструментов.
- [ ] Экраны в клиенте: «Подключённые агенты» в профиле и раздел в администрировании; EN + RU.
- [ ] Уведомление владельцу при административном отзыве.
- [ ] Runbook: порядок действий при подозрении на компрометацию токена агента.
